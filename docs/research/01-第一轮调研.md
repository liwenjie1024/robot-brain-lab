## 1. 先定"像人"的意思

人和机器人逐项对应如下。"仿真里怎么做"一栏是这个项目要实现的东西。

| 人有的 | 人体里是什么 | 机器人里对应 | 仿真里怎么做 |
|---|---|---|---|
| 骨骼和关节 | 约 206 块骨、几百个关节。常用的人体模型 SMPL-X 用 55 个关节 | 连杆 + 转动关节，通常 20~50 个自由度 | MuJoCo 的刚体 + 关节，用代码（MjSpec）生成 |
| 肌肉 | 600 多块，成对拉动（一块收缩、一块放松） | 关节电机（大多数机器人），或绳索/肌腱驱动 | 电机模型（力矩上限、速度上限、减速比、摩擦），或肌肉模型（见 2.4） |
| 本体感觉 | 肌梭（肌肉长度、速度）、高尔基腱器（拉力） | 关节编码器（角度、角速度）、电机电流（力矩） | 关节角度、角速度、力矩传感器，加噪声和分辨率 |
| 平衡感 | 内耳前庭：半规管（转动）、耳石（加速度、重力方向） | IMU（陀螺仪 + 加速度计） | IMU 传感器。人的前庭在头里，所以头上和骨盆上各放一个 |
| 足底感觉 | 脚底的压力感受器 | 足底力传感器 | 脚跟、脚尖的力 → 压力中心（CoP），是平衡的关键信号 |
| 触觉 | 四种感受器：Merkel（持续压力、形状）、Meissner（轻触、滑动）、Pacinian（高频振动）、Ruffini（皮肤拉伸）。指尖最密 | 触觉皮肤（压力阵列），指尖装高分辨率的 | MuJoCo 的 touch grid：每个格子给压力和切向力。指尖密，手掌中等，手臂和躯干稀 |
| 视觉 | 两只眼，眼球能转（扫视） | 头部双目相机，多数机器人眼睛不能转 | 头部两台相机渲染 RGB + 深度 |
| 听觉 | 两只耳朵，能听出声音的方向 | 麦克风阵列 | **MuJoCo 没有声音**，要自己做：碰撞和事件产生声源，按距离、方向算到两只"耳朵" |
| 痛觉 | 伤害感受器，触发缩手反射 | 过载、超限、撞击、过热保护 | 关节超限、力矩过大、撞击力过大、电机过热 → 保护反射 |
| 内部感觉 | 体温、疲劳、饥饿 | 电机温度、电量 | 电机发热模型、电量模型 |

**神经系统的分层和反应时间**，直接对应机器人控制的分层和频率：

| 人 | 做什么 | 大致反应时间 | 机器人对应的层 | 频率 |
|---|---|---|---|---|
| 脊髓反射 | 牵张反射、缩手 | 30~50 ms | 关节控制 + 保护反射 | 1 kHz |
| 前庭眼反射 | 头动时眼睛反向转，视线不晃 | 约 10 ms | 头部和视线稳定 | 200 Hz 以上 |
| 脑干、小脑 | 姿势调整、平衡、动作协调 | 50~150 ms | 全身平衡和行走策略 | 50~200 Hz |
| 运动皮层 | 有意识的动作 | 看到后约 200 ms 开始动 | 技能策略（伸手、抓、走到某处） | 10~50 Hz |
| 基底核 | 选择做哪个动作 | - | 技能选择 | 1~10 Hz |
| 前额叶 | 计划、理解语言 | 秒级 | 语言模型计划 | 0.1~1 Hz |

上一个项目（BL-01）已经分成 System 0/1/2 三层。这次按人的神经系统分得更细，每层的频率也照着人来定。

## 2. 身体的结构

### 2.1 参考机型

| 机型 | 身高 / 体重 | 自由度 | 特点 | 出处 |
|---|---|---|---|---|
| Unitree G1 | 1.32 m / 约 35 kg | 23（EDU 带灵巧手最多 43） | 最常用的研究机型，很多开源训练代码以它为例。最大关节力矩 120 N·m | 官方页面、用户手册 |
| Unitree H2 | 约 1.8 m / 约 70 kg | 31（每条腿 6、每条手臂 7、腰 3、头 2） | 成人大小。腿峰值力矩约 360 N·m | 第三方页面，**未核实** |
| Berkeley Humanoid Lite | 约 1 m / 约 16 kg | 22 个驱动 | 3D 打印的摆线减速器，硬件、嵌入式代码、训练代码全部开源，硬件成本低于 5000 美元 | 论文（RSS 2025） |
| ToddlerBot | 小型 | 30 | 全部 3D 打印，为收集数据设计，开源 | 论文（Stanford） |
| MyoFullBody（仿真人体，不是机器人） | 人体 | 123 个关节，416 块肌肉 | MuJoCo 的肌肉骨骼模型，Hill 型肌肉 | 论文（2026） |

### 2.2 自由度分配（建议的第一版）

| 部位 | 人 | 常见机器人 | 建议第一版 | 理由 |
|---|---|---|---|---|
| 腿 | 髋 3、膝 1、踝 2、脚趾 1 | 每条 6（没有脚趾） | **每条 7**（加脚趾关节） | 人走路靠脚趾蹬地。没有脚趾，步态就不像人 |
| 腰、脊柱 | 很多节椎骨 | 1~3 | 3（转、侧弯、前后弯） | 先用一节代替整条脊柱 |
| 肩带（锁骨、肩胛） | 有 | 几乎都没有 | 第一版没有，以后可以加 | 手举过头、往前伸时更像人 |
| 手臂 | 肩 3、肘 1、前臂转 1、腕 2 | 每条 7 | 每条 7 | 和人一样 |
| 颈 | 3 | 0~2 | 3 | 走路时要靠颈稳住头和视线 |
| 眼 | 每只眼可以转 | 固定相机 | 第一版固定，以后加眼球转动 | 主动看（扫视、追踪）。见第 6 节和 humen 的关系 |
| 手 | 约 27 块骨，20 多个自由度 | 6 个驱动带 12 个关节（常见灵巧手），到 20 多个驱动 | 第一版每只手 12 个关节、6 个驱动：四指各 1 个驱动带动 2~3 个联动关节，拇指 2 个；以后做完整手 | 先能抓，再做灵巧 |

第一版合计：
- 身体 34 个自由度：腿 14、腰 3、颈 3、手臂 14
- 两只手 24 个关节，用 12 个驱动

### 2.3 尺寸和质量

- 身体各段的长度、质量、转动惯量，按人体测量学的数据定（例如 de Leva 1996 的各段质量比例）。关节活动范围也照人来定。这样做出来的比例和人一样。
- 有两个选择：
  - **成人**：约 1.70 m、约 65 kg。和人的动作捕捉数据最匹配，但平衡更难，真机也更贵。
  - **儿童**：约 1.3 m，接近 G1。容易平衡，以后做真机便宜。
- 沿用上一个项目的做法：模型建两次。第一次实测质量、重心、惯量，再按实测值定电机力矩上限，然后重建。

### 2.4 驱动方式

| | A. 关节电机 | B. 肌肉-肌腱 | C. 电机 + 串联弹性 |
|---|---|---|---|
| 像人程度 | 动作像，"用力的方式"不像 | 最像人（416 块肌肉） | 介于两者之间，关节有弹性 |
| 和真机的对应 | 几乎所有真机都是这种 | 很少有对应的真机 | 部分真机（踝、膝） |
| 控制、学习难度 | 成熟，开源代码多 | 很难：几百个肌肉信号 | 比 A 难一点 |
| 仿真速度 | 快 | 慢 | 快 |
| 人的动作数据 | AMASS → GMR 转换后能直接用 | 要另外换算成肌肉信号 | 和 A 一样 |

**建议 A**，并且把电机模型做真实：
- 力矩-转速曲线、力矩上限
- 减速比带来的转子惯量（armature）、摩擦
- 发热

踝和膝以后可以试 C。B 作为以后的研究线，比如用 MyoFullBody 当"人类老师"做对照。

### 2.5 感觉的仿真细节

| 感觉 | 放在哪 | 输出 | 频率 | 要注意 |
|---|---|---|---|---|
| 关节角度、角速度 | 每个关节 | 弧度、弧度/秒，加编码器分辨率和噪声 | 1 kHz | 真机的读数不完美，仿真也要加误差 |
| 关节力矩 | 每个驱动 | N·m | 1 kHz | |
| IMU | 头、骨盆 | 角速度、加速度、姿态 | 200 Hz~1 kHz | 加偏移和漂移 |
| 足底压力 | 每只脚的脚跟、脚掌、脚趾 | 力 → 压力中心 | 500 Hz | |
| 触觉皮肤 | 指尖（密）、手掌、手臂、躯干（稀） | 每格压力 + 切向力；滑动从切向力的变化推出 | 100~500 Hz | MuJoCo 的盒子形状只在顶点算接触，要把碰撞形状切细，分辨率才够。格子越多仿真越慢，要实测 |
| 视觉 | 头部两台相机 | RGB + 深度 | 30 Hz | 渲染占显卡。训练平衡和行走时一般不渲染，只用本体感觉 |
| 听觉 | 头两侧 | 声音事件（种类、方向、响度），以后可能做真音频 | 事件 | 要自己做，MuJoCo 没有 |
| 保护 | 每个关节 | 超限、过载、撞击、过热 | 1 kHz | 触发保护反射 |

## 3. 用什么仿真

| 平台 | 是什么 | 这台电脑能不能用 | 状态 |
|---|---|---|---|
| MuJoCo 3.5（CPU） | 上个项目用的物理引擎 | 能（Linux 容器里，已用过） | 稳定 |
| MuJoCo Warp（GPU） | MuJoCo 的显卡版，同时跑几千个环境 | 能（容器里显卡可用，2026-11-09 实测） | MuJoCo 3.5.0（2026-02-12）起正式发布。和 MuJoCo 功能基本相同，PGS 求解器和 noslip 还不支持 |
| mjlab | Isaac Lab 风格的训练框架，跑在 MuJoCo Warp 上。自带 G1 的速度跟踪、动作跟踪（BeyondMimic）任务 | 能（需要 NVIDIA 显卡，要实测 8GB 能开多少环境） | PyPI 上有 1.6.0 |
| MuJoCo Playground | DeepMind 的 GPU 训练环境集，包括 G1、H1、T1、Berkeley Humanoid 的行走 | 能 | 论文写一张显卡几分钟练出行走（2025） |
| Isaac Lab / Isaac Sim | NVIDIA 的仿真训练平台 | **不能**：要 16GB 显存和 32GB 内存，这台是 8GB | Isaac Sim 6.2 |
| Newton | NVIDIA、DeepMind、Disney 合做的新物理引擎，基于 Warp，MuJoCo Warp 是其中一部分 | 以后再看 | 2025-09 起在 Isaac Lab 里有测试版 |

**建议用 MuJoCo 一家**，同一个身体模型用在两处：

1. **实时身体**：CPU MuJoCo，1 kHz，网页和大脑连上来看、来控制，和上个项目一样。
2. **大规模训练**：MuJoCo Warp + mjlab，同时跑几千个身体，训练平衡、行走、动作跟踪。

模型是同一个，训练出来的策略放回实时身体时，差别只有"仿真到仿真"，没有引擎差异。

## 4. 每一层用什么 AI 模型

| 层 | 对应的人 | 做什么 | 方法和模型 | 数据 | 频率 |
|---|---|---|---|---|---|
| 1. 关节控制 + 保护反射 | 脊髓 | 力矩控制、限位、过载缩回 | 经典控制（PD、阻抗控制），**不训练** | - | 1 kHz |
| 2. 全身平衡和行走 | 脑干、小脑 | 站立、走、跑、被推后恢复 | 强化学习（PPO）+ 域随机化（随机改摩擦、质量、延迟）+ 由易到难的课程；先训练能看到全部仿真信息的"老师"，再教只看传感器的"学生" | 仿真里自己产生 | 50 Hz |
| 3. 模仿人的动作、动作基元 | 运动皮层、小脑 | 跟着人的动作做；学成可复用、可组合的动作空间 | 动作跟踪：BeyondMimic（翻跟头、侧手翻上了真机）、GMT（一个策略跟很多动作）、TWIST；动作空间：ASE 一类 | AMASS 人体动作库 → GMR 转换到机器人关节 | 50 Hz |
| 4. 手的操作和触觉 | 运动皮层 + 体感皮层 | 抓握、按重量调抓力、防滑 | 模仿学习（ACT、Diffusion Policy）加触觉输入，或带触觉的强化学习 | 人的示范（遥操作）+ 仿真 | 10~50 Hz |
| 5. 感知 | 视觉、听觉、体感皮层 | 物体、深度、人的姿态、声音、语音 | YOLO、SAM 2、Depth Anything V2；Whisper、SenseVoice；触觉信号处理（滑动检测） | 预训练好的 | 10~30 Hz |
| 6. 技能选择 / VLA | 基底核 | 看 + 听 + 话 → 选技能或直接出动作 | GR00T N1.6（3B 参数，开源，以 Cosmos Reason 为推理骨干，能边走边操作），π0（openpi，开源）；或自己的技能库 + 选择器 | 机器人数据微调 | 1~10 Hz |
| 7. 计划和对话 | 前额叶 | 听懂命令、多步计划、和人说话 | Qwen3-VL 4B / 8B（本机运行） | 不训练，或少量微调 | 0.1~1 Hz |
| 8. 记忆和再训练 | 海马、睡眠 | 记下经历，离线再训练 | rosbag2 录制 → LeRobotDataset 格式（Parquet + MP4，人形数据集常用） | - | 离线 |

要点：
- **1~3 层不用语言模型**，是小而快的控制和策略网络。3 层就是之前聊的"把小动作组合起来"：先学会跟踪人的各种动作，再把它们学成一个可以调参数、可以组合的动作空间。
- **GR00T 也把模型分成 System 2（慢，视觉语言）和 System 1（快，出动作）**，和上一个项目的分法一样。
- **许可证要先查**：
  - AMASS 和 SMPL-X 只许非商业研究。
  - Ultralytics YOLO 是 AGPL-3.0。
  - GR00T N1.6、π0 的许可证用之前再确认。

## 5. 整个系统的结构

```text
┌──────────────── Linux 容器（Docker，可用显卡）────────────────────────┐
│ 身体：MuJoCo 1 kHz                                                     │
│   └ 层 1：关节控制 + 保护反射（不训练）                                 │
│ ROS 2（节点都放在容器里）                                               │
│   /joint_states  /imu/head  /imu/pelvis  /foot_pressure  /tactile/*     │
│   /camera/left  /camera/right  /audio/events  /clock（仿真时间）        │
│        │                                                               │
│        ├─▶ 层 5 感知节点（显卡）─▶ 物体、人、声音                       │
│        └─▶ 层 2/3 全身策略（50 Hz）◀─ 技能和目标 ◀─ 层 6 技能选择      │
│                                                    ◀─ 层 7 计划和对话   │
│   rosbag2 录制 ─▶ LeRobot 数据 ─▶ 层 8 再训练                           │
└───────────────────────────────────────────────────────────────────────┘
Windows：网页画面（3D、各种感觉的可视化：触觉热力图、足底压力中心、关节力矩）
         ◀─ rosbridge 或 Foxglove bridge
训练：  同一个身体模型 ─▶ mjlab（MuJoCo Warp，几千个并行）─▶ 权重（ONNX）─▶ 策略节点
```

和上一个项目不同的地方：

1. **一开始就用 ROS 2 当主干**。
   - 图像、触觉阵列这样的大数据多了，节点也多，用 ROS 2 的标准消息：`sensor_msgs/JointState`、`Imu`、`Image`，触觉自己定义消息。
   - DDS 出不了 Docker Desktop 的虚拟机，所以 ROS 2 节点全部放在容器里，网页从外面经 bridge 连进来。这是上次实测得出的。
2. **大脑以 Python 为主**。PyTorch 和各种模型都在 Python 里。网页还是 TypeScript。
3. **训练和实时用同一个身体模型**，见第 3 节。
4. **沿用上次有用的规矩**：
   - 规约只在一处定义。
   - 超出范围的命令拒绝，不裁剪。
   - 用身体报告的值评分。
   - 人的指令优先于大脑。
5. **安全层**：任何命令先过关节限位、力矩、速度检查，再到电机。

## 7. 建议路线

每一段都能单独验收，用实测的数值来判断。

| 阶段 | 做什么 | 怎么算做完 |
|---|---|---|
| P1 身体 | 人体比例模型 + 电机模型 + 全部感觉；网页里能看到每种感觉 | 质量、惯量实测；传感器数值合理；用 PD 能站住不倒 |
| P2 平衡 | 站立平衡、被推后恢复；经典控制和强化学习对比 | 能承受的最大推力；恢复时间 |
| P3 行走 | 按速度命令走；由易到难的地形 | 速度跟踪误差、摔倒率 |
| P4 模仿人 | AMASS → GMR → 动作跟踪；动作基元库 | 跟踪误差；能做的动作数 |
| P5 手和触觉 | 抓握 + 按重量调抓力 + 防滑反射 | 不同重量、软硬的物体的成功率 |
| P6 感知 | 视觉、听觉 | 识别准确率、延迟 |
| P7 大脑 | 技能选择 + 计划 + 对话 | 命令完成率 |
| 以后 | 真机：例如 Berkeley Humanoid Lite（约 5000 美元，全开源），或买现成机型 | - |

## 8. 需要你决定的事

1. **目的**：只做仿真研究平台，还是以后要做真机？这决定尺寸和电机模型要做多真实。
2. **驱动**：关节电机（建议）、肌肉-肌腱，还是两条线都做？
3. **尺寸**：成人约 1.7 m，还是儿童约 1.3 m？
4. **手**：第一版简化（12 个关节、6 个驱动），还是一开始就做完整的手？
5. **大脑的主要语言**：Python（建议），还是继续 TypeScript？
6. **文档和画面的语言**：中文，还是韩语？
7. **humen** 以后要不要接？
8. **名字**：项目名和机体名。还是不用现有作品的名字和设计。
