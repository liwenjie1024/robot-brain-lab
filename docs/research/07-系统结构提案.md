# Nova 系统结构提案 v0.1

状态：**提案，待讨论**。2026-11-09。
用户的要求：先设计出最合理的整体系统结构；硬件按最合适的类型选，**不考虑现在能不能买到**。
身体按 [机体规格 v0.2](../机体规格.md)：98 个自由度、90 个驱动器、全身触觉、9 台相机、6 个麦克风。

**v0.1 的修改**（用户问"一台计算机跑各种系统，是不是现在最合理的"，查了以后改）：
- 原来：三台独立计算机（实时、快 AI、慢 AI）+ 安全控制器。
- 现在：**一台中央计算机，分成三个互相隔离的分区**（实时、AI、安全），加上外部安全控制器和每个关节的驱动器。
- 理由见第 4 节。软件的分层不变，只是放的位置变了。

## 0. 一句话

**像人的神经系统一样分层：越往下越快、越简单、越可靠；越往上越慢、越聪明。上层坏了，下层照样能保持平衡、安全地停下。**
- 硬件：一台中央计算机，用虚拟化分成三个互相隔离的分区。
  - 实时分区：脊髓和小脑
  - AI 分区：大脑皮层
  - 安全分区：保底
- 另外有独立的安全控制器，每个关节的驱动器也有自己的小处理器。
- 软件：
  - 最下面两层用 C++，跑在实时分区，1 kHz。
  - 上面全部用 Python 和 ROS 2。
  - 仿真和真机只换最底下的硬件接口，上面一行代码都不改。

## 1. 设计原则

| 原则 | 做法 | 为什么 |
|---|---|---|
| 1. 按时间尺度分层 | 每层有自己的频率；层与层之间只传**目标**和**状态** | 人也是这样：脊髓不懂语言，前额叶不管每块肌肉 |
| 2. 下层不依赖上层 | 每层有"命令过期就保持"的规则；上层停了，下层自己退到安全状态 | 大脑卡住时机器人不能倒（人睡着了也不会从椅子上掉下来） |
| 3. 硬实时只在最下面 | 1 kHz 的关节控制和反射放在隔离出来的实时分区里，不经过普通的消息系统 | 平衡和保护不能被 AI 计算的忙闲影响 |
| 4. 计算集中，故障隔离 | 主计算放在一台计算机上（数据不用跨网络复制）；用分区把故障关在里面；最后的保底在计算机外面 | 见第 4 节 |
| 5. 仿真和真机同一套代码 | 只换硬件接口：真机是 EtherCAT，仿真是 MuJoCo | 仿真里测过的，就是真机上跑的 |
| 6. 规约只写一处 | 身体描述、传感器、观测和动作的格式，都从一个来源生成 | 上一个项目的经验。训练和部署对不上（关节顺序、缩放），是仿真到真机最常见的错 |
| 7. 什么都记录 | 所有传感器、命令、事件、软件版本都记下来 | 用来训练、比较、查问题 |
| 8. 人优先、安全最优先 | 安全分区和安全控制器能压过所有层；人的直接命令能压过 AI | 和上一个项目一样 |

## 2. 分层（对应人的神经系统）

```text
L7 计划和对话（前额叶）                 0.1~1 Hz      AI 分区（GPU 的"慢"部分）
  ↓ 技能请求（可以取消、可以被抢占）
L6 技能选择 / VLA（基底核）             1~10 Hz       AI 分区（GPU 的"慢"部分）
  ↓ 技能目标、动作块
L3 动作生成（运动皮层）                 50 Hz         AI 分区（GPU 的"快"部分）
L4 手臂和手的操作（运动 + 体感皮层）     30~200 Hz     AI 分区（GPU 的"快"部分）
  ↓ 全身参考动作（L3）、上半身目标（L4）
L2 全身平衡和动作跟踪（脑干、小脑）      100~200 Hz    实时分区
  ↓ 每个关节：目标角度、目标速度、前馈力矩、刚度、阻尼
L1 关节控制和反射（脊髓）               1 kHz         实时分区
  ↓ EtherCAT
驱动器（电流环 20~40 kHz）、传感器

旁边的四个部分：
L5 感知（感觉皮层）：把看到、听到、摸到的变成"世界状态"，给 L3、L4、L6、L7 用    AI 分区（GPU 的"快"部分）
丘脑（感知调度）：决定哪台相机、哪块皮肤用多高的频率和分辨率（注意力）            AI 分区
下丘脑（内稳态）：电量、温度、电机疲劳 → 降额、要求休息或充电                    实时分区
安全：心跳监视、停止逻辑                                                       安全分区 + 外部安全控制器
```

### 每层做什么

| 层 | 输入 | 输出 | 做什么 | 方法 |
|---|---|---|---|---|
| L1 关节控制和反射 | L2 的关节目标；1 kHz 的关节、IMU、力、触觉 | 每个驱动器的命令 | 阻抗控制（按刚度、阻尼跟目标）；关节空间 ↔ 驱动器空间换算（并联推杆、肌腱）；状态估计（身体位置、速度、接触）；**反射**（见下表） | 经典控制，不训练 |
| L2 全身平衡和跟踪 | 身体状态；L3 的参考动作；L4 的上半身目标；行走命令 | 全部关节的目标 | 一个通用的全身跟踪策略：跟参考动作，同时保持平衡；手臂在做事时，自动用腿和腰补偿 | 强化学习（BeyondMimic 一类），C++ 里跑 ONNX |
| L3 动作生成 | 技能目标 | 全身参考动作（带未来一小段） | 从动作基元库组合动作：走、坐、捡、跳…… | 动作基元 / 生成模型 |
| L4 操作 | 物体和接触的世界状态；技能目标 | 手臂和手的目标 | 伸手、抓、放、用工具 | 模仿学习 + 触觉 |
| L5 感知 | 相机、麦克风、触觉 | 世界状态（物体、人、地面、声音、接触） | 看、听、摸，记住周围 | 视觉、语音、触觉模型 |
| L6 技能选择 | 世界状态、指令、记忆 | 技能和参数，或者直接给动作块 | 现在做什么技能 | VLA 或技能库 + 选择器 |
| L7 计划和对话 | 话、世界状态、记忆 | 技能请求的序列、回答 | 听懂、计划、对话、解释 | 语言模型 |
| L8 记忆和学习 | 全部记录 | 新的模型 | 整理数据、训练、评分、发布新版本 | 离线，机器人外面 |

### L1 里的反射（全部 1 kHz，不经过 AI）

| 反射 | 触发 | 动作 | 人的对应 |
|---|---|---|---|
| 保护 | 超限、过载、过热 | 限制或降额 | 疼痛缩回 |
| 碰撞 | 力矩突变、皮肤受力 | 变软、退开 | 碰到东西缩回 |
| 防滑 | 指尖切向力和振动的变化 | 加一点抓力 | 东西要滑时自动握紧（人约 60~80 ms） |
| 前庭眼反射 | 头部 IMU | 眼反向转，视线不晃 | 前庭眼反射（约 10 ms） |
| 跌倒 | 身体姿态超出能救回的范围 | 切换到保护性摔倒 | 摔倒时伸手撑地 |
| 停止 | 安全分区或上层要求 | 执行 2 / 1 / 0 类停止 | - |

## 3. 关节的使用权

同一个关节可能有几个上层想用：
- L2 要用手臂保持平衡。
- L4 要用手臂拿东西。
- L3 要做一个全身动作。
- 人在遥控。

所以把身体分成几块，每块同一时间只有一个"主人"，换主人时平滑过渡（约 0.1 秒）：

| 身体部分 | 平时的主人 | 可以接管的 |
|---|---|---|
| 腿和骨盆 | L2（一直） | 没有。平衡永远由 L2 负责 |
| 躯干 | L2 | L3（全身动作） |
| 每条手臂、每只手 | L4 | L3（全身动作）、人的遥控 |
| 头和颈 | 注视控制（L5 的注意力） | L3 |
| 眼 | 注视控制；前庭眼反射一直叠加在上面 | - |

优先级：安全 > 人的直接命令 > L3/L4/注视控制。
L2 一直知道上半身在做什么（上半身的目标是它的输入之一），所以拿重东西时腿会自动补偿。
NVIDIA 的 GR00T 全身控制把下半身（强化学习）和上半身（逆运动学）拆开。研究发现完全拆开会失去平衡，所以 Nova 让 L2 把上半身也考虑进去。

## 4. 硬件结构

### 4.1 业界现在怎么做

| 机器人 | 计算机的结构 |
|---|---|
| Agility Digit | NVIDIA Halos（据 NVIDIA）：**一台计算机**，用虚拟化分成 Linux 区（跑 AI）和 QNX 安全区；另有物理隔离的片上安全岛（独立电源和时钟，SIL 3 能力），载板上还有单独的安全单片机 |
| Tesla Optimus | 主计算机在躯干里，和汽车用的同一种（据报道）；车用版本是双芯片，互为备份 |
| 小鹏 IRON | 3 颗自研 Turing 芯片组成一套计算（约 2250 TOPS），全部在机器人上运行 |
| Figure | 机器人上两块 GPU，慢的视觉语言模型（7~9 Hz）和快的动作策略（200 Hz）各用一块 |
| Unitree G1 | 两台计算机：封闭的运动控制计算机 + 给开发者的 Jetson Orin NX，两者之间走 DDS。分开主要是为了把运动控制封闭起来 |
| 工业软件 | 分区内核（如 SYSGO PikeOS）：一颗芯片上隔出实时区和 Linux 区，Linux 或 AI 那边出错不影响实时区 |

**趋势是：主计算集中到一台计算机上，用分区隔离故障；最后的保底放在计算机外面；每个关节有自己的小处理器。** 没有人真的"什么都放在一起"。

### 4.2 Nova 的硬件

| 部分 | 做什么 | 类型（按最合适的选，不管现在能不能买到） |
|---|---|---|
| **中央计算机**（一块板） | 机器人上全部的计算 | 高性能芯片：多核 CPU + 大 GPU + 片上安全岛（IGX Thor 一类） |
| └ 实时分区 | L1、L2、状态估计、下丘脑、实时记录；EtherCAT 主站 | 隔离出来的 CPU 核，实时 Linux（PREEMPT_RT） |
| └ AI 分区 | L3~L7、L5 感知、丘脑、记录 | Linux。GPU 分成"快"（感知、操作，要低延迟）和"慢"（VLA、语言模型）两个互相隔离的实例 |
| └ 安全分区 | 监视各分区的心跳，执行停止逻辑 | 片上安全岛（独立电源和时钟），或安全虚拟机（QNX） |
| **外部安全控制器** | 急停按钮、无线急停、STO 线、制动器、电池管理；中央计算机整个坏掉时做 0 类停止 | 独立的安全单片机，和中央计算机互相监视 |
| **驱动器** ×90 | 电流环、编码器、温度、短路制动 | 每个一块小处理器。手的微型电机经前臂的驱动板 |
| 触觉读取板 | 把几千个格子打包 | 分布在皮肤下面。指尖走 EtherCAT（给防滑反射），其它走以太网 |
| 相机 ×9、麦克风 ×6 | - | 直接接中央计算机。相机和 IMU 硬件触发 |
| 机器人外面 | 网页、开发电脑、训练服务器 | Wi-Fi 或有线，经 Zenoh 路由器 |

分区之间由虚拟化层隔离（"互不干扰"）：AI 分区崩溃，或者把内存带宽占满，都不影响实时分区。GPU 的两个实例也互不拖慢：语言模型算得再慢，也不影响感知和手的操作。

### 4.3 坏了一部分时怎么办

| 坏了什么 | 结果 |
|---|---|
| GPU 的"慢"实例卡住（语言模型、VLA） | 感知、操作、平衡都不受影响；做完当前技能后站着保持平衡 |
| AI 分区整个崩溃 | 实时分区照样保持平衡，做 2 类停止（站着）或 1 类停止（蹲下后断电）；AI 重启后继续 |
| 实时分区出错 | 安全分区发现心跳停了 → 0 类停止（断扭矩 + 短路制动，慢慢坐下） |
| 中央计算机整个坏掉（硬件、电源、过热） | 外部安全控制器 → 0 类停止，慢慢坐下 |
| 外部安全控制器坏了 | 安全分区接管急停输入（两边互相监视） |

**一个想法（P1 里在仿真中试）**：每个驱动器里预存一个"慢慢坐下"的动作。中央计算机整个坏掉时，安全控制器让所有驱动器同时执行它。这样不用中央计算机也能做到接近 1 类的停止，像脊髓里的保底动作。

### 4.4 为什么比三台独立计算机（v0）更合理

| 方面 | 三台独立计算机（v0） | 一台中央计算机分区（v0.1） |
|---|---|---|
| 软件出错时 | 物理隔离 | 虚拟化隔离 + GPU 实例隔离。已有通过安全认证的平台，够用 |
| 硬件坏了时 | AI 那台坏了还能做 1 类停止 | 整台坏了只能 0 类（慢慢坐下）；加上驱动器预存的动作，可以接近 1 类 |
| 数据传递 | 慢 AI（VLA）要的图像要跨网络传 | 共享内存，不复制 |
| 重量、耗电、散热、布线 | 三套 | 一套 |
| 坏的概率 | 三块板 | 一块板 |
| 开发 | 三种环境 | 一种。和这台电脑上用容器开发的方式一样，每个容器相当于一个分区 |
| 业界 | Unitree（为了开放开发） | Agility Digit、Tesla、小鹏 IRON 的方向 |

**用电**：中央计算机满负荷约 100~150 W（Thor 一类是 40~130 W），比三台合计的约 250 W 少。

## 5. 软件结构

### 5.1 通信

| 数据 | 走哪里 | 为什么 |
|---|---|---|
| 1 kHz 的关节命令和状态 | **不走消息系统**：实时分区里的 ros2_control 控制环 + 共享内存；到驱动器走 EtherCAT | 确定的时间，微秒级抖动 |
| L2 策略 | 作为 ros2_control 里的一个控制器，在同一个实时环里以 100~200 Hz 运行 | 不经过网络，延迟最小 |
| 相机、触觉这种大数据 | 处理它的节点放在**同一个进程**里（ROS 2 进程内零拷贝） | 不复制大数据 |
| 层与层之间（L3~L7）、跨分区、工具 | ROS 2 话题、服务、动作 | 标准，工具多 |
| ROS 2 的底层通信 | **rmw_zenoh**（ROS 2 的 Zenoh 通信层，从 Kilted 版起是一级支持） | 靠路由器互相发现，不靠组播：在 Docker 里、跨分区、跨网络都能连。上一个项目里 DDS 出不了 Docker 虚拟机，这样就解决了 |
| 机器人外面（网页、开发电脑、云） | Zenoh（路由器）；浏览器经 Foxglove bridge 或我们自己的 WebSocket 网关 | 能过 Wi-Fi、能过公网，只转需要的话题 |

技能请求用 ROS 2 的 **action**：有目标、有进度、有结果，可以取消。上层改主意时能打断下层。

### 5.2 规约（只写一处）

1. **身体描述**：用 Python 代码（MjSpec）写一次。由它生成：
   - 完整机构的 MJCF（推杆闭链、肌腱、弹簧）
   - 简化训练用的 MJCF
   - URDF（给 ROS 工具）
   - 关节和驱动器表（范围、减速比、力矩-转速曲线）
   - 传感器表（位置、坐标系、频率、噪声）
2. **观测和动作的规约**：每个策略的输入（哪些关节、什么顺序、怎么缩放、几步历史）和输出（哪些关节、默认姿势、刚度）。
   - 训练环境（mjlab）和部署（实时分区里的 C++ 控制器）读同一个文件。
   - 不一致时直接拒绝运行，不猜。
3. **消息类型**：层间的 ROS 2 消息和动作，在一个包里定义。

### 5.3 语言

| 部分 | 语言 | 为什么 |
|---|---|---|
| L1、L2（实时分区） | **C++** | 1 kHz 硬实时，Python 做不到（垃圾回收、全局锁会造成停顿）；ros2_control 是 C++ |
| 策略的运行 | C++ 里的 ONNX Runtime / TensorRT | 训练在 Python 里，导出成 ONNX，在 C++ 里跑。GR00T 全身控制也是这样部署 |
| L3~L8、工具、训练 | **Python** | 决定过：大脑主要用 Python |
| 安全分区、外部安全控制器、驱动器 | C（或 Rust） | 固件 |
| 网页 | TypeScript（Vue + three.js），中文 | 和上一个项目一样 |

说明：之前定的"大脑主要用 Python"不变。L1、L2 相当于脊髓和小脑的"固件"，所以用 C++。

### 5.4 时间

- **一个时钟**：
  - 真机：中央计算机是时钟源，各分区共用芯片的时钟。EtherCAT 用分布式时钟，相机和 IMU 硬件触发；机器人外面的设备用 PTP 对时。
  - 仿真：全部用仿真时间。
- 每条数据都带"什么时候测的"，不是"什么时候收到的"。

## 6. 仿真和真机

```text
真机：实时分区 ── EtherCAT 硬件接口 ── 驱动器、传感器
仿真：实时分区（容器）── MuJoCo 硬件接口 ── MuJoCo 1 kHz（完整机构、全部传感器、延迟、噪声）
      ↑ 上面的 L1~L8 完全一样
```

- MuJoCo 已经能作为 ros2_control 的硬件接口（mujoco_ros2_control）：控制器和配置不变，只换硬件插件。
- 仿真里要模拟的，不只物理：
  - 每种传感器的延迟、噪声、标定误差
  - EtherCAT 的周期
  - 驱动器的力矩-转速曲线、发热
  - 自己做的声音模型
- **三种运行方式**：

| 方式 | 做什么 | 用在哪 |
|---|---|---|
| 实时 | 和墙上的钟一样快 | 在网页上看、和人一起试 |
| 同步 | 仿真每走一步，等所有控制器算完，结果完全可重复 | 自动测试、试验和评分（上一个项目的经验：同一时间接管就得到同一结果） |
| 快速 | 不渲染，尽量快 | 大批量评估 |

- **训练**：mjlab（MuJoCo Warp，显卡上几千个并行），用简化模型 + 同一份观测和动作规约。训练好的策略导出 ONNX，先在完整机构的仿真里验收，再上真机。

### 在这台电脑上（开发阶段）

**每个容器相当于真机上的一个分区**，结构和真机一样。

| 容器 | 相当于 | 内容 |
|---|---|---|
| nova-sim | 身体和驱动器 | MuJoCo（CPU）+ 相机渲染（GPU） |
| nova-rt | 实时分区 | ros2_control + L1 + L2（C++）。Docker Desktop 的内核没有实时补丁，所以开发时用"同步"方式，不需要硬实时 |
| nova-safety | 安全分区 + 外部安全控制器 | 心跳监视、停止逻辑（模拟） |
| nova-perception | AI 分区（快） | L5、丘脑（GPU） |
| nova-brain | AI 分区（快 + 慢） | L3、L4、L6、L7（Python） |
| zenoh | - | 路由器 |
| nova-gateway | - | 网页网关 |
| nova-record | - | 记录 |
| nova-train | 机器人外面 | 训练（GPU，需要时才开） |

显卡只有 8 GB，所以按工作内容分组启动，不同时全开：
- 平衡开发：只开仿真 + 实时 + 安全
- 操作开发：再加感知
- 大脑开发：再加语言模型

## 7. 数据和学习（L8）

```text
运行（仿真或真机）→ 全部记录（rosbag2，MCAP 格式）→ 挑出片段 → LeRobot 数据集（v3：Parquet + MP4）
  → 训练（强化学习在仿真里；模仿学习用示范）→ 新策略（ONNX + 规约 + 版本信息）
  → 自动评估（同步方式的试验和评分）→ 比旧版本好才发布 → 先在完整仿真里，再上真机；可以随时退回旧版本
```

- **每次运行都记下所有版本**：身体描述、每个模型、配置。这样两次结果能比较（上一个项目的试验和评分思路）。
- **示范数据**：人通过遥控（VR 或动作捕捉）教 Nova 做事，记录下来用于模仿学习。

## 9. 延迟目标

| 回路 | 路径 | 目标 | 人 |
|---|---|---|---|
| 保护和碰撞反射 | 力矩、皮肤 → L1 → 驱动器 | ≤ 2 ms | 脊髓反射 30~50 ms |
| 防滑反射 | 指尖触觉 → L1 → 手指 | ≤ 5 ms | 60~80 ms |
| 前庭眼反射 | 头部 IMU → L1 → 眼 | ≤ 5 ms | 约 10 ms |
| 平衡 | IMU、关节 → L2 → L1 | ≤ 10 ms | 姿势反应 50~150 ms |
| 看到再伸手 | 相机 → L5 → L4 → L2 → L1 | ≤ 100 ms | 约 200 ms |
| 听到话开始回答 | 麦克风 → 语音识别 → L7 → 说话 | ≤ 1 s | 0.2~1 s |

## 10. 考虑过的其它做法

| 方面 | 选的 | 没选的 | 为什么 |
|---|---|---|---|
| 计算机 | 一台中央计算机（实时 / AI / 安全三个分区）+ 外部安全控制器 + 驱动器 | 三台独立计算机（v0） | 见第 4.4 节 |
| | | 一台电脑、不分区 | AI 出错或占满资源，平衡就跟着出问题 |
| 消息系统 | ROS 2 + rmw_zenoh | ROS 2 + Fast DDS | DDS 靠组播互相发现，在 Docker 和跨网络时麻烦；Fast DDS 作为备选，实测后再定 |
| | | dora-rs | 很快（Rust 内核、零拷贝），但很年轻，工具和生态比 ROS 2 少；它报的"比 ROS 2 Python 快 10~17 倍"是项目自己测的 |
| | | 自己写（像 Unitree SDK） | 工具全要自己做 |
| 实时控制 | ros2_control + EtherCAT + 实时 Linux | 全部放单片机 | 单片机放不下 98 个自由度的状态估计和策略；PAL Robotics 的人形机器人用的就是这个组合（1~2 kHz） |
| 策略的运行 | C++ + ONNX/TensorRT | Python | 实时环里不能有停顿 |

## 11. P1 里要先验证的

1. rmw_zenoh 的延迟、CPU 占用、大数据（图像、触觉）的表现；共享内存现在支不支持没查到，要实测。不行就换 Fast DDS。
2. 98 个自由度的完整机构模型，MuJoCo 在 CPU 上能不能稳定跑 1 kHz，同步方式下每一步要多久。
3. ros2_control + MuJoCo 硬件接口在 Docker 里的表现。
4. 8 GB 显卡上能同时开哪些容器。
5. 观测和动作规约：从 mjlab 训练到 C++ 部署，跑通一个最简单的站立策略。
6. 驱动器预存的"慢慢坐下"（4.3 节）在仿真里效果如何。
7. 分区隔离的效果（AI 满负荷时实时分区的抖动），要等有实时内核的机器才能测。这台电脑的 Docker 测不了。

## 12. 要你确认的

1. 一台中央计算机分成实时、AI、安全三个分区，加外部安全控制器：可以吗？
2. L1、L2 用 C++，其余用 Python：可以吗？（"大脑主要用 Python"不变）
3. 消息系统用 ROS 2 + rmw_zenoh，实测不行再换 Fast DDS：可以吗？
4. 关节使用权（第 3 节）：平衡永远由 L2 负责，人的直接命令优先于 AI：可以吗？
5. 还有没有想加的层或功能？比如情绪，或者"自我"的状态。
