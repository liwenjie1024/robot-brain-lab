## 0. 一句话

**4 层，按快慢和可靠性分：越往下越快、越简单、越可靠；越往上越慢、越聪明。上层坏了，下层照样能保持平衡、安全地停下。**
**每层只收它需要的传感器数据**：原始的快数据留在最下面处理掉，往上只传摘要和事件。

- 硬件：一台中央计算机，分成三个互相隔离的分区（实时、AI、安全），加外部安全控制器和每个关节的驱动器。
- 软件：下两层用 C++，在实时分区里跑；上两层用 Python。仿真和真机只换最底下的硬件接口。

## 1. 设计原则

| 原则 | 做法 | 为什么 |
|---|---|---|
| 1. 按快慢和可靠性分层 | 只在"快慢差很多"或"可靠性要求不同"的地方分层 | 分得越多，接口、延迟、出错的地方越多 |
| 2. 下层不依赖上层 | 每层有"命令过期就保持"的规则；上层停了，下层自己退到安全状态 | 大脑卡住时机器人不能倒（人睡着了也不会从椅子上掉下来） |
| 3. 每层只收需要的数据 | 原始数据在最下面处理掉；往上传摘要和事件，频率越来越低 | 人走路时意识不到脚底每块皮肤的压力，这些在脊髓和小脑就处理完了。有研究估计人有意识处理的信息每秒只有约 10 比特 |
| 4. 硬实时只在最下面 | 1 kHz 的关节控制和反射放在实时分区，不经过普通的消息系统 | 平衡和保护不能被 AI 的忙闲影响 |
| 5. 计算集中，故障隔离 | 主计算在一台计算机上（数据不用复制）；分区把故障关在里面；最后的保底在计算机外面 | 见第 5 节 |
| 6. 仿真和真机同一套代码 | 只换硬件接口：真机是 EtherCAT，仿真是 MuJoCo | 仿真里测过的，就是真机上跑的 |
| 7. 规约只写一处 | 身体描述、传感器、观测和动作的格式，都从一个来源生成 | 上一个项目的经验。训练和部署对不上（关节顺序、缩放），是仿真到真机最常见的错 |
| 8. 什么都记录 | 所有传感器、命令、事件、软件版本都记下来（不挡在关键路径上） | 用来训练、比较、查问题。产品里按隐私规则记录，见 [商用要求](商用要求.md) |
| 9. 人优先、安全最优先 | 安全能压过所有层；人的直接命令能压过 AI | 和上一个项目一样 |
| 10. 大脑不绑定一个身体 | 训练时随机改身体（质量、肢体的长短、力量），练出来的大脑能用在"一族"身体上；身体是参数，不是写死的 | 真机的参数一定会和仿真里的不一样；身体还会改（手、质量）；以后也好换身体（2026-11-12 加） |
| 11. 分核心和待证明 | 每一项标上"核心"或"待证明"，P1 只做核心；先用现成的身体当基线 | 东西多了，要看得出哪些是必须的。清单在 [核心和待证明](核心和待证明.md)（2026-11-12 加） |

## 2. 分层：4 层 + 两条旁路

```text
思考脑（前额叶）          1~10 Hz     AI 分区·GPU 慢实例    看几张图、听懂话、想计划、说话
  ↓ 现在要做的子任务（可以随时改、随时取消）
动作脑（运动和感觉皮层）   30~200 Hz   AI 分区·GPU 快实例    看相机、摸触觉 → 走路命令、手臂和手的目标、全身动作
  ↓ 身体命令：走的速度和方向、上半身目标、全身参考动作
小脑层（脑干、小脑）       50~200 Hz   实时分区              保持平衡，把身体命令变成全部关节的目标
  ↓ 每个关节：目标、刚度、阻尼、前馈力矩
脊髓层（脊髓）            1 kHz       实时分区              关节控制 + 全部反射
  ↓ EtherCAT
驱动器（电流环 + 本地的阻抗环，每秒 1 万~4 万次）、传感器

旁路 1：安全（安全分区 + 外部安全控制器）——不靠 AI，有自己的一套最少的传感器
旁路 2：记录和学习——全部记录；训练在机器人外面做
```

2026-11-12 加的两点说明：
- 动作脑的 30~200 Hz 是**命令**的频率。模型一次出一段动作（动作块），自己每秒只算十几到二十几次（GR00T N1.7 在 Thor 上约 25~28 次，只带 1 台相机）。
- 关节的阻抗环在驱动器里跑；脊髓层每秒 1000 次给它目标和软硬。

### 为什么是 4 层

每一条分界线，都是两边的快慢或可靠性要求差得很多：

| 分界 | 上面 | 下面 | 为什么不能合并 |
|---|---|---|---|
| 思考脑 / 动作脑 | 能懂话、会推理的大模型，几十亿参数，每秒只能算几次 | 每秒要出 30~200 次动作 | 大模型来不及。Figure Helix（慢 7~9 Hz / 快 200 Hz）和 GR00T 都这样分 |
| 动作脑 / 小脑层 | 看相机的模型，可能卡住、可能看错 | 平衡 | **平衡不能依赖视觉模型**：模型卡住时也要站得住。GR00T 把全身控制和 VLA 分开；Helix 的快模型只管上半身，走路另有控制器 |
| 小脑层 / 脊髓层 | 训练出来的策略，50~200 Hz | 1 kHz 的关节控制和反射 | 所有用强化学习走路的机器人都这样：策略给目标，下面的 1 kHz 控制去跟 |

再少就会出问题：要么平衡依赖大模型（不安全），要么要求大模型每秒算几百次（现在做不到）。
这和上一个项目（BL-01）也对得上：思考脑 = System 2（慢脑），动作脑 = System 1（快脑），小脑层 + 脊髓层 = System 0（身体的控制）。

| v0 | v0.2 |
|---|---|
| L1 关节控制和反射 | 脊髓层 |
| L2 全身平衡和跟踪 | 小脑层 |
| L3 动作生成、L4 手臂和手的操作、L6 技能选择 | **动作脑**：一个"看了就动"的通用模型为主，做不好的技能用专门的小模型补 |
| L5 感知 | 大部分**在模型里面**（动作脑、思考脑直接看图像）；少数几样做成小模块，放在用它的地方（见下表） |
| L6 的理解部分、L7 计划和对话 | **思考脑** |
| 丘脑（注意力） | 动作脑的一部分：看哪台相机、看哪块区域 |

还要保留的小感知模块：

| 模块 | 给谁 | 为什么不放进大模型 |
|---|---|---|
| 状态估计（身体的位置、速度、接触） | 脊髓层、小脑层 | 1 kHz，要确定 |
| 地形高度图（胸前看脚下的深度相机一直看着，额头的深度相机补充） | 小脑层（走楼梯、不平的地） | 平衡要用，不能等大模型 |
| 热的东西在哪（热成像相机，温度阈值 + 位置） | 动作脑（别碰）、思考脑（灶开着）、安全（太热的东西靠近人） | 要快、要确定，不用神经网络 |
| 玻璃、镜子（超声波 + 相机，规则判断） | 安全、小脑层 | 深度相机会看穿玻璃；近处的玻璃门要马上知道 |
| 地面有多滑（落脚时足底的切向力和微小的滑动） | 小脑层（调整步子）、脊髓层 | 每一步都要，要快 |
| 视觉惯性里程计（两只眼的相机 + IMU） | 脊髓层的状态估计、思考脑（在家里的位置） | 纠正朝向和位置的漂移，要一直跑、要确定 |
| 飞来物检测（事件相机，看东西是不是在变大） | 脊髓层（飞来物反射） | 要快、要确定，不用神经网络 |
| 附近有没有东西（深度 + 接近觉，只做几何判断，不用神经网络） | 安全 | 安全不能依赖会出错的模型 |
| 声音的前端：回声消除（减掉自己说的话）、自身噪声消除（按电机状态减掉自己的声音）、定位、对准说话的人 | 动作脑（声音的方向）、后面的语音识别 | 要快、要一直跑 |
| 语音识别、声音事件、说话人识别 | 思考脑；危险的声音事件也给安全 | 小而快，专门的模型更准 |
| 关键词"停" | 安全（在**安全分区**里单独运行，AI 卡住也能用） | 安全不能依赖 AI 分区 |

### 每层做什么

| 层 | 输入 | 输出 | 方法 |
|---|---|---|---|
| 脊髓层 | 小脑层的关节目标（和每只手的最小握力）；1 kHz 的原始传感器 | 每个驱动器的命令（目标、软硬、前馈力矩）；哪些关节被限制了（给小脑层） | 关节空间 ↔ 驱动器空间换算（并联推杆、连杆、肌腱和绞盘）；状态估计；反射（见下表）；协调；关节空间的硬限制（安全过滤的第二道）。关节的阻抗环在驱动器里跑（每秒 1 万~4 万次），脊髓层给它目标和软硬。经典控制，不训练 |
| 小脑层 | 身体状态、接触、地形高度图；动作脑的身体命令（含手和手臂的力、软硬） | 全部关节的目标 | 一个通用的全身控制策略：跟身体命令，同时保持平衡；手臂在做事、在用力时，自动用腿和腰补偿；能把手当支撑点（扶扶手、台面、墙）。强化学习，C++ 里跑 ONNX |
| 动作脑 | 相机（缩小、降频）、触觉摘要、身体状态、最近几十秒的画面记忆；思考脑的子任务 | 身体命令：动作，加上手和手臂的力、软硬 | **运行时只有一个策略**：一个视觉-动作模型（像 Helix 的快模型、GR00T 的动作部分）；专门技能和动作生成当"老师"，练进它里面。另有价值模型；以后可以换成世界-动作模型 |
| 思考脑 | 几张图、语音识别的文字、身体状态摘要、当场的短时记忆、做到哪了 | 子任务（一句话 + 指出来 + 目标画面 + 怎么做）、回答 | 视觉语言模型 / 语言模型。不用一个家的模型：在哪里都靠常识和当场看到的来想 |

### 用手扶着保持平衡、楼梯的规则（2026-11-10 加）

- 小脑层能把手当作支撑点：动作脑说"扶这里"（扶手、台面、墙、椅背），小脑层把手的支撑算进平衡。人在厨房里、上下楼、从沙发上起来、够高处的东西时也是这样做的。
- **握力跟着扶的力走**（2026-11-17 加）：小脑层要用手出力（扶、撑、拉）时，同时给脊髓层一个"这只手至少握多紧"的数，脊髓层把握力提到不小于它。不这样的话，脚下一滑、手臂猛拉扶手时，动作脑给的握力来不及跟上，手会被扯开。人也是这样：提的东西越重，手不用想就握得越紧。手指的角度还是动作脑管，不进小脑层。
- 楼梯的规则（安全最优先）：
  - 上下楼一直扶着扶手；走慢。
  - 手里的东西挡住视线、看不到脚下时，不上下楼。
  - 楼梯下面有人时，先等一等。

### 运动的安全过滤（2026-11-12 加）

动作脑是学出来的，说不准什么时候会出错。所以它的命令先过一层**确定的**检查，再交给小脑层：
- 会不会撞到自己。
- 离人多近时，最快能多快：离得越近越慢。
- 力和关节有没有超出包线。家里有人时用**家用包线**：速度、力、重心高度的上限。
- 不合格就改小；改不了就停。

它放在实时分区，不用神经网络；上限由安全分区定，AI 改不了。

**第二道在脊髓层**（2026-11-17 加）：小脑层自己也是学出来的，遇到没见过的情况（被猛推、传感器出毛刺）也可能给出不对的关节目标。所以脊髓层每秒 1000 次再查一遍关节空间的硬限制：力矩、速度、功率、关节的角度、碰到东西时的力（腕、踝、指尖），超了就改小。哪些关节被限制了，告诉小脑层（它的输入之一），免得它不知道、还接着用力。也不用神经网络，上限由安全分区定。
参考：SHIELD 在 Unitree G1 真机上做过这样的过滤，能给出概率意义上的保证。

### 先想一想（2026-11-11 加）

人做有风险的事之前，会在心里预演：叠高了会不会倒，倒水会不会洒。
- 思考脑和动作脑在做有风险的事之前（叠高、倒水、搬重东西、靠近人），可以调用"世界模型"想象做了以后会怎样，再决定做不做、怎么做。
- **第一个用处：目标画面**（2026-11-11 定）：每个子任务开始时，世界模型（首选 Cosmos 3 Nano 的生成部分，备选 Cosmos Predict 2.5）画出这一步做完应该是什么样，交给动作脑（6.1 节、[AI 模型](AI模型.md) 第 4 节）。**按需画**（2026-11-17 改）：机上的电脑里 CPU 和 GPU 共用一条内存的路，画图特别占这条路，会拖慢动作脑（GPU 分了实例也一样）。所以平时子任务只给一句话和指出来的点；只在没把握、连续失败、停下来想的时候才画；联网时可以交给基站或云画。
- 叠高、倒水这类风险的预演：先留接口（输入是现在看到的和打算做的动作，输出是想象的结果和风险），等世界-动作模型（GR00T N2 一类）成熟再接。

### 脊髓层的反射（全部 1 kHz，不经过 AI）

| 反射 | 触发 | 动作 | 人的对应 |
|---|---|---|---|
| 保护 | 超限、过载、过热 | 限制或降额 | 疼痛缩回 |
| 肌腱保护 | 手的肌腱张力过大，或者松了 | 限力；重新预紧 | - |
| 碰撞 | 力矩突变、皮肤受力 | 变软、退开 | 碰到东西缩回 |
| 防滑 | 指尖切向力和振动的变化 | 加一点抓力 | 东西要滑时自动握紧（人约 60~80 ms） |
| 脚底防滑 | 足底切向力突然变化、脚的 IMU | 踝变硬、重心往回收，同时告诉小脑层 | 踩到滑的地方先反射，然后才意识到 |
| 前庭眼反射 | 头部 IMU | 眼反向转，视线不晃 | 前庭眼反射（约 10 ms） |
| 跌倒 | 身体姿态超出能救回的范围 | 切换到保护性摔倒 | 摔倒时伸手撑地 |
| 飞来物 | 事件相机发现东西朝脸飞来 | 闭眼睑、转头、抬手挡 | 东西飞来时眨眼、躲开 |
| 停止 | 安全或上层要求 | 执行 2 / 1 / 0 类停止 | - |

## 3. 传感器数据怎么走：每层只收需要的

| 传感器 | 原始频率 | 脊髓层 | 小脑层 | 动作脑 | 思考脑 | 安全 |
|---|---|---|---|---|---|---|
| 关节编码器、电机电流 | 1 kHz | 全部原始数据 | 关节位置、速度（50~200 Hz） | 手臂和手的（30 Hz） | 只要"正常 / 哪里有问题" | 一份冗余的 |
| IMU ×8（骨盆两个互相对照） | 1 kHz | 原始 | 身体姿态、角速度 | 身体状态摘要 | - | 跌倒检测 |
| 足底压力、踝部力 | 0.5~1 kHz | 原始 → 压力中心 | 接触状态、压力中心 | - | - | - |
| 指尖、手掌的触觉和振动 | 200~500 Hz（振动 2 kHz） | 变化通道（防滑反射） | - | 接触摘要：接触点、力的方向和大小、有没有在滑（30 Hz） | - | - |
| 全身皮肤、接近觉 | 100 Hz | 碰撞反射 | - | 接触事件、社交触觉（被拍肩膀、握手、拥抱） | "有人拍我"一类的事件 | 撞到人就停 |
| 眼的相机 ×2 | 周围 60 帧、中央凹 60~120 帧 | - | - | 中央凹小块 + 缩小的周围（10~30 Hz） | 几张（1~10 Hz） | - |
| 胸前看脚下的深度相机 | 30 帧 | - | 地形高度图（一直） | 需要时 | - | 脚下和前面有没有障碍 |
| 超声波 ×3 | 约 20 Hz | - | 前面有没有玻璃、镜子 | - | - | 玻璃门、镜子 |
| 额头深度相机、环视相机 | 30 帧 | - | 地形高度图（补充） | 需要时 | - | 附近有没有人和东西 |
| 热成像相机 | 约 10~30 帧 | - | - | 热的东西在哪（别碰） | 摘要（灶开着、锅很烫） | 太热的东西靠近人 |
| 手掌相机 ×2 | 30 帧 | - | - | 抓东西时 | - | - |
| 事件相机 | 微秒级 | 飞来物反射 | - | 快速运动（接球） | - | - |
| 麦克风 ×6 | 48 kHz（同一个时钟） | - | - | 声音方向（转头）、叫名字 | 文字、情绪、谁在说、声音事件 | "停"（安全分区里单独识别）、烟雾报警 |
| 气体传感器（嗅觉） | 1~10 Hz | - | - | - | 闻到了什么（烧焦、异味） | 燃气、一氧化碳、烟 → 安全的动作（不开关电器、告诉人） |
| 温度、电量、冷却液（温度、流量、漏液）、机身进水、驱动器的振动 | 1~10 Hz | 降额 | - | - | 摘要（要不要歇一会、要不要充电、哪个零件快坏了） | 过热、漏液、进水就停 |

"记录"收全部数据，但写盘不挡在关键路径上；视频压缩后存。

规则：
1. **原始的快数据留在最下面**，由脊髓层处理掉。
2. **往上只传摘要和事件，频率越来越低。** 脚底的压力是脊髓层和小脑层的事；只有"踩到钉子"这种事件才往上报。
3. **图像只给看图的模型**，而且按需要缩小、降频。注视点高清，周围低清，像人的眼睛。
4. **安全有自己的一套最少的传感器**（IMU、关节、皮肤、接近觉、急停），算法简单确定，不经过 AI。
5. **在一台中央计算机里，"传递"基本就是共享内存**：传感器写一次，谁需要谁读，不复制（发布 / 订阅）。这也是改成一台计算机的好处之一：以前分三台时，图像要跨网络传给另一台。

每层每秒的数据量（估计）：

| 层 | 每秒 |
|---|---|
| 脊髓层 | 约 6~8 MB（原始的关节、IMU、指尖和足底触觉，在本地处理；触觉只报变化时少得多） |
| 小脑层 | 几十 KB |
| 动作脑 | 约 10~30 MB（缩小后的图像在 GPU 内存里，不复制） |
| 思考脑 | 约 1~2 MB |
| 安全 | 很少 |
| 记录 | 约 30~100 MB（视频压缩） |

## 4. 关节的使用权

同一个关节可能有几个上层想用，所以把身体分成几块，每块同一时间只有一个"主人"，换主人时平滑过渡（约 0.1 秒）：

| 身体部分 | 平时的主人 | 可以接管的 |
|---|---|---|
| 腿和骨盆 | 小脑层（一直） | 没有。平衡永远由小脑层负责 |
| 躯干 | 小脑层 | 动作脑（全身动作） |
| 每条手臂、每只手 | 动作脑 | 人的遥控 |
| 头、颈、眼 | 动作脑（注视）；前庭眼反射一直叠加在上面 | 人的遥控 |

优先级：安全 > 人的直接命令 > 动作脑。
手扶着东西时：手放在哪由动作脑定，扶的力由小脑层定（平衡要用）。
动作脑里同一时间只有一个策略在出命令（2026-11-12 加）。过渡期（专门技能还没练进主模型时）：由思考脑在子任务里点名用哪个，切换时平滑过渡。

**注视（看哪里）**：动作脑每秒决定 2~3 次，按 安全 > 任务 > 社交 > 探索 打分。小的移动只动眼，大的先动眼、头跟着转。视线也是沟通：家里的人看 Nova 在看什么，就知道它要做什么。
小脑层一直知道上半身在做什么（上半身的目标是它的输入之一），所以拿重东西时腿会自动补偿。
GR00T 的全身控制把下半身（强化学习）和上半身（逆运动学）拆开；研究发现完全拆开会失去平衡，所以 Nova 让小脑层把上半身也考虑进去。

| 小鹏 IRON | 3 颗自研 Turing 芯片组成一套计算（约 2250 TOPS），全部在机器人上运行 |
| Figure | 机器人上两块 GPU，慢的视觉语言模型（7~9 Hz）和快的动作策略（200 Hz）各用一块 |

**趋势是：主计算集中到一台计算机上，用分区隔离故障；最后的保底放在计算机外面；每个关节有自己的小处理器。**

### 5.2 Nova 的硬件

| 部分 | 跑什么 | 类型（按最合适的选，不管现在能不能买到） |
|---|---|---|
| **中央计算机**（一块板） | 机器人上全部的计算 | 高性能芯片：多核 CPU + 大 GPU + 片上安全岛（IGX Thor 一类）。做成能换的模块：算力两三年换一代（2026-11-12 加） |
| └ 实时分区 | 脊髓层、小脑层、状态估计、地形高度图、实时记录；EtherCAT 主站 | 隔离出来的 CPU 核，实时 Linux（PREEMPT_RT） |
| └ AI 分区 | 动作脑（GPU 快实例）、思考脑（GPU 慢实例）、语音、记录 | Linux。GPU 的两个实例互相隔离：思考脑算得再慢，也不拖慢动作脑 |
| └ 安全分区 | 监视各分区的心跳，执行停止逻辑，安全用的几何判断，关键词"停"的识别；碰到人的力和速度不超过 ISO/TS 15066 给的人身体各部位的上限 | 片上安全岛（独立电源和时钟），或安全虚拟机（QNX） |
| **外部安全控制器** | 急停按钮、无线急停、STO 线、制动器、电池管理；中央计算机整个坏掉时做 0 类停止 | 独立的安全单片机，和中央计算机互相监视 |
| **驱动器** ×90 | 电流环、本地的阻抗环（每秒 1 万~4 万次）、最硬的保护反射、编码器、温度、振动、短路制动、预存的"坐下"动作 | 每个一块小处理器；氮化镓的驱动板放在关节里。腿和腰的 15 个关节是双绕组电机，各两个驱动器。手的微型电机经前臂的驱动板；手的防滑反射也放在前臂的板上 |
| **电源** | 电池 + 母线上的超级电容 | 高倍率电芯；超级电容瞬间补大功率、制动时收回能量，电池断开时撑几秒（机体规格第 13 节） |
| 触觉读取板 | 把几千个格子打包 | 分布在皮肤下面。指尖走 EtherCAT（给防滑反射），其它走以太网 |
| 相机 ×11、麦克风 ×6、扬声器 ×1、气体传感器 | - | 直接接中央计算机。麦克风用同一个时钟。相机和 IMU 硬件触发。相机原始约 450 MB/s，进图像处理器和 GPU 内存后不再复制 |
| 机器人外面 | 网页、开发电脑、训练服务器；可选的增强：家里的基站或云上更大的模型（2026-11-12 加） | Wi-Fi 或有线，经 Zenoh 路由器。机上的模型是完整的，连不上也能做事；连得上时用更大的模型。动作块的做法能容忍 200~300 ms 的延迟 |

### 5.3 坏了一部分时怎么办

| 坏了什么 | 结果 |
|---|---|
| 思考脑卡住 | 动作脑做完当前子任务；站着保持平衡，等思考脑恢复 |
| 动作脑卡住 | 小脑层保持平衡，做 2 类停止（站着）；手臂停在原处 |
| AI 分区整个崩溃 | 实时分区照样保持平衡，做 2 类或 1 类停止（蹲下后断电） |
| 实时分区出错 | 安全分区发现心跳停了 → 0 类停止：驱动器先执行预存的"坐下"动作，再断扭矩 + 短路制动 |
| 中央计算机整个坏掉（硬件、电源、过热） | 外部安全控制器 → 0 类停止：同上 |
| 腿或腰的一个驱动器、一套绕组坏了 | 另一套还能出约一半的力：1 类停止（蹲下），或走到安全的地方 |
| 电池突然断开 | 超级电容撑几秒：驱动器执行预存的"坐下"动作，把手里的东西放低 |
| 完全没电（电池和超级电容都没了） | 膝和髋的制动器夹紧、打滑，身体慢慢降下来；手里的东西会掉（手指不自锁，短路制动握不住）。所以超级电容单独监控，电不够时提前停下来、先放下手里的东西 |
| 外部安全控制器坏了 | 安全分区接管急停输入（两边互相监视） |

**驱动器里预存的"坐下"动作，是掉电和 0 类停止的主方案**（2026-11-12 定；原来只是一个想法）：中央计算机整个坏掉或者电池断开时，安全控制器让所有驱动器同时执行它，用超级电容的电。这样不用中央计算机也能做到接近 1 类的停止，像脊髓里的保底动作。
为什么升为主方案：膝和踝改成低减速比以后，短路制动的阻尼小了一个数量级以上（粗算），光靠它不能保证"慢慢"坐下。P1 里重新仿真。

### 5.4 为什么比三台独立计算机（v0）更合理

| 方面 | 三台独立计算机（v0） | 一台中央计算机分区 |
|---|---|---|
| 软件出错时 | 物理隔离 | 虚拟化隔离 + GPU 实例隔离。已有通过安全认证的平台，够用 |
| 硬件坏了时 | AI 那台坏了还能做 1 类停止 | 整台坏了只能 0 类（慢慢坐下）；加上驱动器预存的动作，可以接近 1 类 |
| 数据传递 | 思考脑要的图像要跨网络传 | 共享内存，不复制 |
| 重量、耗电、散热、布线 | 三套（合计约 250 W） | 一套（约 100~150 W） |
| 坏的概率 | 三块板 | 一块板 |
| 开发 | 三种环境 | 一种。和这台电脑上用容器开发的方式一样 |

### 5.5 可靠性设计和求助（2026-11-09 加）

成功 = 人能依靠 Nova（见 [Nova 考试](Nova考试.md)）。可靠性靠设计，不是最后才修：

| 设计 | 做法 |
|---|---|
| 自检 | 开机时检查每个传感器、关节范围、驱动器温度；运行中互相对照（两个传感器说的不一样就报警）；看电机温度、电流和振动的变化趋势，提前发现快坏的零件；看相机的画面脏不脏（模糊、斑点） |
| 自己恢复 | 摔倒 → 保护性摔倒 → 自己站起来；东西掉了 → 重新抓；卡住 → 退回去换个做法再试（次数有上限）→ 还不行就求助 |
| 降级 | 5.3 节的分区退法；另外还有功能上的降级：一只手坏了用另一只，一台相机坏了用别的 |
| **求助** | 判断自己没把握时（见下面），先停在安全的姿势，然后说话问家里的人，或者请远程的人接手 |
| 远程协助 | **遥控系统同时就是远程协助系统**：远程的人戴 VR 接手，帮 Nova 做完。家里的人看得到有人接手（头上的指示灯、手机上的提示），可以拒绝，事后能查记录 |
| 求助变成数据 | 每次求助、每次接手的过程都录下来，进数据飞轮。下次遇到同样的情况，Nova 自己就会做了 |
| 故意制造困难 | 考试和训练都随机，并且注入故障：传感器坏、通信变慢、驱动器失效、地面打滑、被推 |
| 失败排行 | 每次失败自动归类，统计"最常见的失败"，排在前面的先解决 |
| 发布规则 | Nova 考试不退步才发布新版本；随时能退回旧版本 |
| 判断上的安全 | 用话写的行为准则：不该做的事，比如把刀递给小孩、把毛绒玩具放在热的灶上。思考脑的每个计划先过这一关；考试有专门的题。参考 Google DeepMind 的 ASIMOV（2026-11-12 加） |

**怎么判断"没把握"**：
- **价值模型**（[AI 模型](AI模型.md) 第 3 节④）估计的"能做成的可能性"低，或者突然往下掉。
- 动作脑、思考脑给出的把握程度低：多次生成的动作差别很大。
- 碰到的情况和训练时见过的差别太大。
- 同一件事失败了几次。
- 任务好一阵没有进展。
- 安全相关的情况（附近有小孩、要拿刀或热的东西）一律先问人。

### 5.6 网络安全（2026-11-10 加）

家里的机器人有相机、麦克风，能被远程接手，还连着云。被人攻破的后果比手机严重得多：能看、能听，还能动。
真实的例子：2025 年 Unitree G1 等机器人的蓝牙配网接口被发现能直接拿到最高权限（密钥写死在固件里），被攻破的机器人还能去攻破附近的其它机器人。

| 做法 | 内容 |
|---|---|
| 只运行签过名的东西 | 安全启动；软件和 AI 模型都要签名才能运行；升级也要签名，能退回 |
| 不留后门 | 没有写死的密钥和默认密码；不用的接口（蓝牙等）默认关掉 |
| 加密 | 机器人里外的通信都加密；云和远程协助要强认证 |
| 远程接手 | 每次都要家里的人同意，随时能收回（5.5 节） |
| **安全的上限谁都改不了** | 远程的人、AI、云发来的命令，都超不过安全分区定的速度和力的上限 |
| 记录 | 谁在什么时候连过、做了什么 |
| 补漏洞 | 有公开的漏洞报告渠道，及时打补丁 |
| 标准 | IEC 62443、ETSI EN 303 645（消费类联网设备）、欧盟无线设备的网络安全要求（EN 18031 系列） |

## 6. 软件结构

### 6.1 通信

| 数据 | 走哪里 | 为什么 |
|---|---|---|
| 1 kHz 的关节命令和状态 | **不走消息系统**：实时分区里的 ros2_control 控制环 + 共享内存；到驱动器走 EtherCAT | 确定的时间，微秒级抖动 |
| 小脑层的策略 | 作为 ros2_control 里的一个控制器，在同一个实时环里以 50~200 Hz 运行 | 不经过网络，延迟最小 |
| 相机、触觉这种大数据 | 处理它的模型和节点放在**同一个进程**里（ROS 2 进程内零拷贝），图像留在 GPU 内存里 | 不复制大数据 |
| 动作脑 → 小脑层、思考脑 → 动作脑、工具 | ROS 2 话题、服务、动作 | 标准，工具多 |
| ROS 2 的底层通信 | **rmw_zenoh**（ROS 2 的 Zenoh 通信层，从 Kilted 版起是一级支持） | 靠路由器互相发现，不靠组播：在 Docker 里、跨分区、跨网络都能连。上一个项目里 DDS 出不了 Docker 虚拟机，这样就解决了 |
| 机器人外面（网页、开发电脑、云） | Zenoh（路由器）；浏览器经 Foxglove bridge 或我们自己的 WebSocket 网关 | 能过 Wi-Fi、能过公网，只转需要的话题 |

思考脑给动作脑的子任务用 ROS 2 的 **action**：有目标、有进度、有结果，可以取消。思考脑改主意时能打断动作脑。
子任务里有（2026-11-11 加）：一句话、结构化参数、**指出来**（画面上的点和框，思考脑的模型给出）、**目标画面**（异步，晚一点到也不挡动作；只在需要时画，见第 2 节"先想一想"）、**怎么做**（开始时和没把握时的几句话）、**示范**（可选：一段人做这件事的视频，2026-11-12 加）、优先级。都是人看得懂的：网页上能看到 Nova 想做什么、想做成什么样。

### 6.2 规约（只写一处）

1. **身体描述**：用 Python 代码（MjSpec）写一次。由它生成：
   - 完整机构的 MJCF（推杆闭链、肌腱、弹簧）
   - 简化训练用的 MJCF
   - URDF（给 ROS 工具）
   - 关节和驱动器表（范围、减速比、力矩-转速曲线）
   - 传感器表（位置、坐标系、频率、噪声，以及第 3 节"给哪层、什么形式"）
2. **观测和动作的规约**：每个策略的输入（哪些关节、什么顺序、怎么缩放、几步历史）和输出（哪些关节、默认姿势、刚度）。
   - 训练环境（mjlab）和部署（实时分区里的 C++ 控制器）读同一个文件。
   - 不一致时直接拒绝运行，不猜。
3. **消息类型**：层间的 ROS 2 消息和动作，在一个包里定义。

### 6.3 语言

| 部分 | 语言 | 为什么 |
|---|---|---|
| 脊髓层、小脑层（实时分区） | **C++** | 1 kHz 硬实时，Python 做不到（垃圾回收、全局锁会造成停顿）；ros2_control 是 C++ |
| 策略的运行 | C++ 里的 ONNX Runtime / TensorRT | 训练在 Python 里，导出成 ONNX，在 C++ 里跑。GR00T 全身控制也是这样部署 |
| 动作脑、思考脑、工具、训练 | **Python** | 决定过：大脑主要用 Python |
| 安全分区、外部安全控制器、驱动器 | C（或 Rust） | 固件 |
| 网页 | TypeScript（Vue + three.js），中文 | 和上一个项目一样 |

说明：之前定的"大脑主要用 Python"不变。脊髓层、小脑层相当于"固件"，所以用 C++。

### 6.4 时间

- **一个时钟**：
  - 真机：中央计算机是时钟源，各分区共用芯片的时钟。EtherCAT 用分布式时钟，相机和 IMU 硬件触发；机器人外面的设备用 PTP 对时。
  - 仿真：全部用仿真时间。
- 每条数据都带"什么时候测的"，不是"什么时候收到的"。

## 7. 仿真和真机

```text
真机：实时分区 ── EtherCAT 硬件接口 ── 驱动器、传感器
仿真：实时分区（容器）── MuJoCo 硬件接口 ── MuJoCo 1 kHz（完整机构、全部传感器、延迟、噪声）
      ↑ 上面的四层完全一样
```

- MuJoCo 已经能作为 ros2_control 的硬件接口（mujoco_ros2_control）：控制器和配置不变，只换硬件插件。
- 仿真里要模拟的，不只物理：
  - 每种传感器的延迟、噪声、标定误差
  - EtherCAT 的周期
  - 驱动器的力矩-转速曲线、发热
  - 自己做的声音模型
  - 听觉（MuJoCo 没有声音）：分两级。声音事件级（大规模训练、大部分考试）：只记声源的种类、位置、响度、说的话，按几何算出 Nova 听到的方向和响度并加误差。波形级（验证耳朵和音频处理）：按 3D 场景算房间的回声（SoundSpaces 2.0 一类），算出每个麦克风收到的声音，加上自己的电机声和自己说的话。随机化回声、背景声、麦克风
  - 视觉：训练用 MuJoCo Warp 的批量渲染器（光线追踪，快但不够真实）；相机模型（畸变、噪声、曝光、运动模糊，深度的飞点和空洞，事件相机由高帧率渲染生成）两边共用；随机化纹理、灯光、相机参数；以后用手机扫描真实的家，做成照片级的考场（3D 高斯泼溅的外观 + 网格的碰撞）
  - 触觉：CPU 的 MuJoCo 用 touch_grid；GPU 训练（MuJoCo Warp 不支持插件传感器）用自己写的快速虚拟触觉。两套输出同一格式，在测试场景上对比读数。传感器的毛病（模糊、噪声、迟滞、漂移、串扰、坏格子、延迟）两套共用；振动、温度、接近觉自己合成
  - 发热：每个驱动器、主电脑、电池的热模型，加上液冷回路；策略在仿真里学会管理温度
  - 气味（MuJoCo 没有气味）：像声音事件一样，按来源和扩散算浓度（燃气、烧焦、烟）
  - **每种传感器都要连毛病一起模拟**（2026-11-11 定）：深度相机会看穿玻璃、镜子里有"假东西"；镜头会脏；超声波斜照到玻璃时收不到回声；指尖热感按材料的导热算热流；地面分块随机摩擦，加上水洼。这样模型才学得会"什么时候不能全信它"。选传感器也看这一条：仿真里模拟不好的（比如偏振相机）先不用
  - 缺口：MuJoCo 的渲染画不出玻璃的折射（只能半透明）。P1 里实测 MuJoCo Warp 能不能；不能就另用渲染器做玻璃的数据
- 考场（家、物品、家里的人、体能场）和裁判见 [Nova 考试](Nova考试.md) 第 2、4 节。裁判直接读仿真的状态判分，不经过 Nova 的四层，也不信 Nova 自己报的
- **三种运行方式**：

| 方式 | 做什么 | 用在哪 |
|---|---|---|
| 实时 | 和墙上的钟一样快 | 在网页上看、和人一起试 |
| 同步 | 仿真每走一步，等所有控制器算完，结果完全可重复 | 自动测试、试验和评分（上一个项目的经验：同一时间接管就得到同一结果） |
| 快速 | 不渲染，尽量快 | 大批量评估 |

- **训练**：mjlab（MuJoCo Warp，显卡上几千个并行），用简化模型 + 同一份观测和动作规约。训练好的策略导出 ONNX，先在完整机构的仿真里验收，再上真机。
- **动作脑也"老师教学生"**（2026-11-11 加）：老师在仿真里能看到全部信息，用强化学习练；动作脑是学生，只看相机和触觉，跟着老师学。家、物品、任务由程序生成，**从一开始就用很多个家**；裁判自动判成败（[AI 模型](AI模型.md) 第 7 节）。
- **仿真的保底**（2026-11-12 加）。数据主要来自仿真，所以要防着"只在这个仿真里行"：
  - **换引擎再考**：在 MuJoCo 里练的策略，放到另一个物理引擎（Newton、Isaac）里再考一次。换了引擎就不行的，上真机多半也不行。
  - **照片级的画面**：用视频生成模型（Cosmos Transfer 2.5 或 Cosmos 3）把仿真渲染的画面变成像真的，形状和动作不变，拿来训练。
  - **身体随机化**：训练时随机改身体（质量、肢体的长短、力量），见第 1 节的原则 10。
  - **驱动也要有仿真模型**：摩擦、迟滞、发热、力矩-速度；肌腱另加蠕变和互相牵连。
- **升级的路**（2026-11-12 加）：
  - 软的东西和水：留好换到 Newton 的路。Newton 1.0（2026 年 3 月，Linux 基金会）里面就有 MuJoCo Warp，还有布料和颗粒、液体的求解器。
  - 考场别从零做：先看 RoboCasa 能用多少。它是 MuJoCo 上现成的家务仿真，RoboCasa365 有 365 个任务、2500 个厨房；代码 MIT，素材 CC BY 4.0。
- **基线**（2026-11-12 加）：先用一个现成的身体把四层和考场跑通：Unitree G1（SONIC 的权重就是给它练的）；NVIDIA 的参考人形机器人的模型公开后再加上。见 [核心和待证明](核心和待证明.md)。

### 在这台电脑上（开发阶段）

**每个容器相当于真机上的一个分区或一层**，结构和真机一样：

| 容器 | 相当于 | 内容 |
|---|---|---|
| nova-sim | 身体和驱动器 | MuJoCo（CPU）+ 相机渲染（GPU） |
| nova-rt | 实时分区 | 脊髓层 + 小脑层（C++）。Docker Desktop 的内核没有实时补丁，所以开发时用"同步"方式，不需要硬实时 |
| nova-safety | 安全分区 + 外部安全控制器 | 心跳监视、停止逻辑、安全用的几何判断（模拟） |
| nova-act | AI 分区·快 | 动作脑、语音（GPU） |
| nova-think | AI 分区·慢 | 思考脑（GPU） |
| zenoh | - | 路由器 |
| nova-gateway | - | 网页网关 |
| nova-record | - | 记录 |
| nova-train | 机器人外面 | 训练（GPU，需要时才开） |

显卡只有 8 GB，所以按工作内容分组启动，不同时全开：
- 平衡开发：只开仿真 + 实时 + 安全
- 操作开发：再加动作脑
- 大脑开发：再加思考脑

## 8. 数据和学习（旁路 2）

```text
运行（仿真或真机）→ 全部记录（rosbag2，MCAP 格式）→ 挑出片段 → LeRobot 数据集（v3：Parquet + MP4）
  → 训练（强化学习在仿真里；模仿学习用示范）→ 新策略（ONNX + 规约 + 版本信息）
  → 自动评估（同步方式的试验和评分）→ 比旧版本好才发布 → 先在完整仿真里，再上真机；可以随时退回旧版本
```

- **每次运行都记下所有版本**：身体描述、每个模型、配置。这样两次结果能比较（上一个项目的试验和评分思路）。
- **示范数据**：人通过遥控（VR 或动作捕捉）教 Nova 做事，记录下来用于模仿学习。

## 10. 延迟目标

| 回路 | 路径 | 目标 | 人 |
|---|---|---|---|
| 驱动器本地的保护（过流、超限、过热） | 就在驱动器里 | ≤ 0.1 ms | - |
| 保护和碰撞反射 | 力矩、皮肤 → 脊髓层 → 驱动器 | ≤ 2 ms | 脊髓反射 30~50 ms |
| 防滑反射 | 指尖触觉 → 脊髓层 → 手指 | ≤ 5 ms | 60~80 ms |
| 脚底防滑反射 | 足底切向力 → 脊髓层 → 踝 | ≤ 5 ms | 自动姿势反应约 70~100 ms |
| 前庭眼反射 | 头部 IMU → 脊髓层 → 眼 | ≤ 5 ms | 约 10 ms |
| 飞来物反射 | 事件相机 → 脊髓层 → 眼睑、颈、手臂 | 约 20 ms | 约 100 ms 左右 |
| 平衡 | IMU、关节 → 小脑层 → 脊髓层 | ≤ 10 ms | 姿势反应 50~150 ms |
| 看到再伸手 | 相机 → 动作脑 → 小脑层 → 脊髓层 | ≤ 100 ms | 约 200 ms |
| 听到话开始回答 | 麦克风 → 语音识别 → 思考脑 → 说话 | ≤ 1 s | 0.2~1 s |
| 子任务开始到目标画面出来 | 思考脑 → 世界模型 → 动作脑 | ≤ 1 s（异步，不挡动作；实测后定） | - |
| 说完"停"到开始停下 | 麦克风 → 安全分区的关键词识别 → 停止 | ≤ 300 ms | - |
| 听到声音到开始转头 | 麦克风 → 定位 → 动作脑 → 颈、眼 | ≤ 200 ms | 简单的听觉反应约 150 ms |
| 被打断到停止说话 | 麦克风 → 回声消除 → 有没有人说话 → 停止说话 | ≤ 200 ms | - |

## 11. 考虑过的其它做法

| 方面 | 选的 | 没选的 | 为什么 |
|---|---|---|---|
| 层数 | 4 层 | 8 层（v0） | 接口和延迟多；很多层其实在模型里面就能做 |
| | | 2 层（一个大模型直接给关节命令） | 平衡和反射会依赖大模型；大模型每秒算不了几百次 |
| 计算机 | 一台中央计算机（实时 / AI / 安全三个分区）+ 外部安全控制器 + 驱动器 | 三台独立计算机（v0） | 见第 5.4 节 |
| | | 一台电脑、不分区 | AI 出错或占满资源，平衡就跟着出问题 |
| 消息系统 | ROS 2 + rmw_zenoh | ROS 2 + Fast DDS | DDS 靠组播互相发现，在 Docker 和跨网络时麻烦；Fast DDS 作为备选，实测后再定 |
| | | dora-rs | 很快（Rust 内核、零拷贝），但很年轻，工具和生态比 ROS 2 少；它报的"比 ROS 2 Python 快 10~17 倍"是项目自己测的 |
| | | 自己写（像 Unitree SDK） | 工具全要自己做 |
| 实时控制 | ros2_control + EtherCAT + 实时 Linux | 全部放单片机 | 单片机放不下 98 个自由度的状态估计和策略；PAL Robotics 的人形机器人用的就是这个组合（1~2 kHz） |
| 策略的运行 | C++ + ONNX/TensorRT | Python | 实时环里不能有停顿 |

## 12. P1 里要先验证的

1. rmw_zenoh 的延迟、CPU 占用、大数据（图像、触觉）的表现；共享内存现在支不支持没查到，要实测。不行就换 Fast DDS。
2. 98 个自由度的完整机构模型，MuJoCo 在 CPU 上能不能稳定跑 1 kHz，同步方式下每一步要多久。
3. ros2_control + MuJoCo 硬件接口在 Docker 里的表现。
4. 8 GB 显卡上能同时开哪些容器。
5. 观测和动作规约：从 mjlab 训练到 C++ 部署，跑通一个最简单的站立策略。
6. 驱动器预存的"慢慢坐下"（5.3 节）在仿真里效果如何。
7. 分区隔离的效果（AI 满负荷时实时分区的抖动），要等有实时内核的机器才能测。这台电脑的 Docker 测不了。
8. 第一个家（约 50 种物品、能开关的家具）加上 Nova，MuJoCo 每一步要多久；快考能不能在几分钟里考完。
9. 热模型和液冷：一轮家务里每个关节的温度，液冷够不够。
10. 小脑层的频率：50~200 Hz 和更高（到 1 kHz）比一比。Figure Helix 02 的全身控制是 1 kHz（自报）。
11. 从动作反推驱动：每个关节的"力矩-速度"曲线；超级电容多大、母线多少伏。
12. MuJoCo Warp 能不能画出玻璃的折射。
13. **质量闭环（第一件事）**：用"驱动器有多重"的模型把体重算到收敛（机体规格第 7 节）。2026-11-14 算了第一遍：核心版 78~97 kg；2026-11-17 驱动器按从动作算的力量算了第二遍：核心版 74~88 kg，见 [报告](报告/质量闭环.md)。
14. 完全没电时的坐下：膝和髋的制动器打滑力矩设多大。
15. 速度的预算表：每个模型多久算一次、算一次多久、占多少算力；目标画面要多久。
16. 基线：现成的身体（G1）跑通四层和考场，分数存档。
17. 换引擎再考：同一个策略在另一个物理引擎里的分数差多少。

## 13. 已确认（2026-11-09）

1. 4 层（思考脑、动作脑、小脑层、脊髓层）+ 安全 + 记录和学习
2. 传感器数据按第 3 节走：每层只收需要的，原始数据在最下面处理掉
3. 一台中央计算机分成实时、AI、安全三个分区，加外部安全控制器
4. 下两层用 C++，上两层用 Python（"大脑主要用 Python"不变）
5. 消息系统用 ROS 2 + rmw_zenoh，实测不行再换 Fast DDS
6. 平衡永远由小脑层负责，人的直接命令优先于 AI
