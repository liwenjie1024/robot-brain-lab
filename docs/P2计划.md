# P2 计划：站和走

2026-11-18 定。计划不用讨论，按 Claude 的想法进行（用户 2026-11-13 定），做一步更新一步。

## 1. P2 要做成什么

**在仿真里让 Nova 自己站稳、被推了不倒、按指令走、上下楼梯、摔倒了自己起来。**
做的是下面两层的第一版（[系统结构](系统结构.md)第 2 节）：

- **小脑层**：一个学出来的策略（神经网络），每秒算 50 次左右（以后和更快的比）。看身体的感觉、脚下的地形和要走的速度，
  告诉每个关节转到哪、多软多硬。
- **脊髓层**：每秒 1000 次，不用 AI。把关节的目标换成每个驱动器的命令（并联的一对按和、差换算）；估出身体在哪、多快、
  朝哪（状态估计）；守住硬的限制（超了就改小，并且告诉小脑层）；基本的反射（保护、碰撞、跌倒、停止）。

**怎么算做完**：第一次考试里"基本"的那几项（[Nova 考试](Nova考试.md)第 3 节 A），用同一个测试台、同一套题，和基线比。
驱动器的限制（力矩和转速、发热、命令的延迟）和传感器的毛病（噪声、零偏、延迟）都开着（1.6 步做的）。

| 题 | 考试里 | P2 做到 |
|---|---|---|
| 站 | 站 1 小时 | 站 1 小时不倒，驱动器不过热 |
| 被推 | 被推了不倒，记扛得住的最大推力 | 前后左右推：扛得住的比 P1 只顶着关节时（往侧面是体重的 10%）大得多，至少和基线一样 |
| 走 | 走 1 公里 | 按指令的速度和方向走（平地，往前 0~1.1 m/s，能横着走、转弯），走 1 公里不摔；记跟上指令的误差、耗电。驱动器的力量是照快走 1.1 m/s 定的 |
| 上下楼梯 | 套内楼梯：一级最高 0.20 m、踏面最窄 0.22 m（比脚还短），14~17 级；一直扶着扶手；故意让它打滑、被碰一下 | 上下一整段不摔，中间被碰一下、踩到滑的一级也不摔。**先不扶扶手**：扶要用手（P4 做）；不扶也走得稳，扶手才是多一道保险 |
| 摔倒了起来 | 摔倒后自己站起来 | 摔的时候护住自己（不摔坏）；从趴着、仰着、侧躺着都站得起来 |

**基线** = Unitree G1（P1 已经放上同一个测试台）：用两种策略考同一套题，SONIC 现成的权重，和用我们自己的办法（mjlab）练的。

**范围**只做"核心"（[核心和待证明](核心和待证明.md)）。小脑层的核心里还有"跟上半身的目标"（2.7 步做）；
"用手扶着""手上的力""握力跟着扶的力走"要有手和东西，放到 P4 和动作脑一起做（P2 先练到手上被拉、被推也站得住）。

## 3. 已经知道的

**2.0 训练的架子**（2026-11-18~19，做完）：

- **训练的容器**（nova-train）：PyTorch 2.14.0（CUDA 13.0）、NVIDIA Warp 1.18.0、MuJoCo Warp 3.17.0、mjlab 1.6.0
  （2026-11-01 的那一版）。下载约 4 GB，镜像 10.6 GB。148 个库的版本都锁在 `train/uv.lock`（只要 2026-11-04 以前发布的）。
- **mjlab 那一版写的是 MuJoCo 3.16，装在 3.17 上能用**：显卡和 CPU 算一个方块落地，结果一样；mjlab 自带的"G1 按指令走"
  练得出来，练出来的策略在我们的测试台上走得起来。要绕开的有四处，都不改 mjlab 的代码：不画图（容器里没有 EGL）；
  没有 git 就不记代码的状态；"解的次数用完了"的提醒关掉（MuJoCo Warp 3.17 每一步都在显卡上打印，30 轮打了一万多行）；
  导出身体模型时按训练的设置另建一份（已经接进训练场景的那一份，3.17 里再复制会崩）。
- **这台电脑练 G1 走路**：4096 个仿真一起跑，每秒约 7 万步（一轮约 1.4 秒），占显存约 1.7 GB；8192 个每秒约 8.7 万步、
  约 3.0 GB。2000 轮用了 49 分钟：最后每一回都站满 20 秒，一次都没摔。
- **练出来的策略在我们的测试台上走得起来**：测试台是 CPU 的 MuJoCo、1 毫秒的步长、测试台的地面（练的时候是显卡、
  5 毫秒、mjlab 的地面）。照一张命令表走：站着，往前 0.5 和 1.0 m/s，边走边转，往左横着走，往后退，停下来。
  七段一次都没摔，速度平均差 0.03~0.06 m/s（往前 1.0 m/s 量到 0.95）。导出的 ONNX 和 PyTorch 算的动作最多差 1.2×10⁻⁶。
- **策略的规约（第一版）**：`contracts/policy/policy.schema.json`。写着策略看什么（IMU 量的速度和角速度、重力的方向、
  关节的角度和转速、上一次的动作、命令）、出什么（每个关节的目标，加上软硬和力矩的上限）、每秒算几次、练过的命令的范围。
  训练那边导出时写它，测试台照它接；对不上（文件的指纹、长度、名字、范围）就不跑。命令超出练过的范围也不跑，不剪。
- **Nova 的模型放进显卡的仿真不用改**（81 个自由度、67 个驱动器、96 个形状、10 根肌腱、254 个传感器）：从站姿站 1 秒，
  和 CPU 上算的一样（骨盆都是 0.892 m）。4096 个一起跑每秒约 17.7 万步，占约 700 MiB 显存（站着时；走起来接触多了还要多些）。
  Nova 的一步比 G1 贵差不多一倍（G1 练的时候连 PPO 一起每秒约 27 万步：7 万 x 4），2.3 步练的时候先把手指固定，会快一些。
- **mjlab 自带的 G1 和测试台的 G1 不一样**（测试台的是 MuJoCo Menagerie 的 `g1.xml`）：碰撞用简单的形状（不用网格），
  关节没有摩擦，转子惯量按电机算，软硬低很多（膝约 99 N·m/rad，测试台的是 500）。2.0 用 mjlab 的那一个（策略是在它上面练的）；
  基线用哪一个，2.2 步定。

**2.1 脊髓层**（做着）：

- **一：换算和硬限制，接到测试台**（2026-11-19，做完）。C++ 写的（`rt/`），测试台经 nanobind 每 1 毫秒调用一次。
  像 Nova 那么大（67 个关节，5 对并联）一步约 1.5 微秒，预算是 1000 微秒。
  - 照模型自己建：每个驱动器带着哪些关节、系数多少（Nova 的踝、腰、腕是两根固定肌腱上的和、差），力的上限；关节的范围、
    峰值力矩（G1 写在关节上的也认得）；有驱动器的模型时再加转速（空载转速）和功率（峰值力矩 x 拐点转速）的上限。
    从驱动器的读数算回关节的角度，和仿真里的一点不差。
  - 并联的一对两个关节软硬不一样时，驱动器那边的软硬不是"各管各的"（有交叉的项）：驱动器自己的阻抗环只管对角的那一项，
    交叉的那部分脊髓层每 1 毫秒按读数算成前馈力。在仿真里真的算一遍：驱动器出的力换回关节，正好是要的力矩（差不到 10⁻⁹）。
  - 硬限制超了就改小，并且告诉是哪一种：目标超出范围（离两头留 0.5°）、力矩超过峰值、转到最快还往这个方向推、
    推的功率超过上限、驱动器出到顶（并联的一对两个关节分着用）。限过的部分从前馈力里扣，目标和软硬照小脑层给的。
  - 策略不直接碰驱动器了：它给每个关节的目标和软硬，脊髓层换成驱动器的命令，驱动器那一层照它出力（命令晚 1 毫秒到）。
    2.0 练的 G1 照样走得稳：七段都没摔，速度差和以前一样。走得快时 G1 的策略会把两个踝（前后）的目标放到关节的范围以外
    （约一成的步），脊髓层把它放回范围里，走路不受影响。Nova 经过脊髓层站着，和以前直接给驱动器目标一模一样。

## 4. 怎么训练、怎么考

- **强化学习**：在显卡上同时跑几千个仿真（MuJoCo Warp），策略一边试一边改，做得好给分（PPO，mjlab 里现成的）。
- **这台电脑的显卡只有 8 GB**：站、走、少量动作练得了（[AI 模型](AI模型.md)第 8 节）。SONIC 那种规模的动作跟踪要几千 GPU 小时，要上云，要花钱，到时候先问。
- **练的和考的是同一个身体**：训练用的模型照 P1 的身体描述生成（同一个 MuJoCo 版本）；驱动器的限制、传感器的毛病训练时也有（并且随机改），练出来的策略到测试台上才站得住。
- **只认测试台的分数**：练完导出 ONNX，在测试台上考（CPU 的 MuJoCo、完整的身体、驱动器和传感器的模型、经过脊髓层）。训练里的分数不算。
- **小脑层在 CPU 上跑**（实时分区）：网络要小，一次 2 毫秒内算完。
- **练出来的动作反过来核对身体**：每个策略考完，看它用了驱动器的多少（峰值力矩、转速、发热），和 P1 定的力量比。不够就回去改身体（质量闭环再算一遍）。
