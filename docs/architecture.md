# 구조

사람형 로봇의 AI 두뇌를 시험하는 곳이다. 실제 휴머노이드처럼 층을 나누고, 층마다 빠르기와 쓰는 기술이 다르다.
시험 대상은 두뇌(System 1·2)이고, 몸과 운동 제어(System 0)는 시험 장치다.

| 층 | 하는 일 | 빠르기 | 쓰는 것 | 상태 |
|---|---|---|---|---|
| 몸 | 관절·접촉·중력 물리 | 500Hz (0.002초) | MuJoCo 3.17 (Python, Linux 컨테이너) | 1단계 완료 |
| System 0 운동 제어 | 걷기 속도 명령 → 균형을 잡으며 걷는 다리 관절 힘 | 정책 50Hz, PD 500Hz | 미리 학습된 강화학습 정책 (Unitree G1) | 1단계 완료 |
| System 1 빠른 뇌 | 목표로 가기, 거리 유지, 피하기, 비상 정지. 언어 모델 없이 되먹임으로 | 20~50Hz | TypeScript | 2단계 |
| System 2 느린 뇌 | 말로 한 명령 + 장면 요약 → 행동 계획(JSON) | 1번에 수백 ms~몇 초 | 로컬 언어 모델 (Ollama, JSON 형식 강제) | 3단계 |
| 시험장 화면 | 3D 모습, 상태, 직접 조종, 명령과 답, (나중에) 층마다 판단 기록과 지연 시간 | 화면 60fps | Vue 3 + three.js | 1단계 완료 |

## 왜 이렇게 나누나

- **느린 뇌가 몸을 직접 움직이면 안 된다.** 언어 모델은 계획 하나에 수백 ms~몇 초가 걸린다. 걷기 균형은 20ms마다,
  피하기·비상 정지는 수십 ms 안에 해야 한다. 그래서 느린 뇌는 "무엇을 할지"만 정하고, 빠른 뇌가 지금 상태를 보며
  "어떻게" 하고, 운동 제어가 넘어지지 않게 한다 (Figure Helix, NVIDIA GR00T N1과 같은 나누기).
- **몸은 시험 장치다.** 걷기 자체를 새로 배우게 하는 일(강화학습)은 연구 수준이라, 공개된 학습 정책을 받아 쓴다.
  나중에 다른 몸(팔 있는 모델, 직접 만든 기체)으로 바꿔도 위 층은 같은 규약(걷기 속도 명령, 상태)만 쓴다.
- **두뇌는 TypeScript로 쓴다.** 나중에 두뇌만 휴대폰(React Native + llama.rn)으로 옮길 수 있게 한다. 몸과 두뇌는
  WebSocket 규약으로만 이어지므로, 두뇌가 PC에 있든 휴대폰에 있든 몸은 모른다.

## 데이터 흐름

```text
시험장 화면 ──GET /scene, /meshes/{id}──▶ 몸(sim :8765)   모양·메시·명령 범위 (한 번)
시험장 화면 ◀──WS /ws  state 50Hz──────── 몸               자세(몸체마다 위치·회전), 로봇 상태(위치·방향·속도·넘어짐)
두뇌·화면   ──WS /ws  velocity/stop/push/reset──▶ 몸       명령 → ack(적용한 시뮬레이션 시각) 또는 rejected(까닭)
```

규약은 `contracts/sim/*.schema.json` 한 곳에서 정한다. 몸은 같은 스키마로 명령을, 화면은 같은 스키마로 메시지를 검증한다.

## 1단계에서 잰 값 (2026-11-03, 이 PC)

| 무엇 | 값 |
|---|---|
| 물리 계산 빠르기 | 실제 시간의 약 46배 (21초를 0.46초에) → 실시간으로 돌리면 CPU 여유가 크다 |
| 앞으로 0.5m/s 명령 | 실제 0.48m/s, 넘어지지 않음 |
| 가장 빠른 앞 1.0m/s | 실제 약 0.89m/s, 넘어지지 않음 |
| 제자리에서 돌기 0.8rad/s | 실제 0.83rad/s |
| 멈춤 명령 | 제자리걸음을 하며 1초에 약 2~6cm 흘러간다 (몇 분이면 몇 m) |
| 밀기 0.1초 | 300N까지 모든 방향에서 버팀, 400N은 앞·옆으로 밀면 넘어짐 (뒤로는 버팀) |
| 밀기 0.2초 | 150N까지 버팀, 400N은 모든 방향에서 넘어짐 |
| 화면에서 보낸 명령 → ack | 12~40ms (제어 주기 20ms 안에서 적용 + 개발 서버 중계) |

멈춤에서 흘러가는 것은 걷기 정책의 성질이다. 위치를 지켜야 하는 일은 System 1이 지금 위치를 보고 고쳐 가는
되먹임으로 해야 한다 (명령만 보내 놓고 믿으면 안 된다).

## 다음 단계

1. **System 1 (빠른 뇌):** 시험장에 목표·장애물·상대(움직이는 물체)를 두고, 목표로 가기·바라보기·거리 유지·피하기·
   넘어질 것 같으면 멈추기를 되먹임으로 한다. 판단마다 기록(무엇을 보고 무엇을 정했는지, 걸린 시간)을 남겨 화면에 보인다.
2. **System 2 (느린 뇌):** 말로 한 명령과 System 1이 요약한 장면(JSON)으로 행동 계획을 만든다. JSON 형식을 강제하고,
   계획을 경계에서 검증한다. 기다리는 동안의 몸짓(필러), 첫 행동부터 바로 시작(스트리밍), 자주 쓰는 명령은 언어 모델 없이 처리.
3. **시험 장면과 점수:** 정해진 장면(목표 찾아가기, 밀려도 일 끝내기, 상대 피하기)을 여러 번 돌려 성공률·지연 시간을 잰다.
4. 나중에: 팔이 있는 몸(윗몸 관절), 두뇌를 휴대폰으로 옮기기, 직접 만든 기체와 걷기 정책 학습(Linux GPU 필요).

## 붙여 받은 계획(다른 AI 정리)에서 바꾼 것

- 휴대폰 카메라 + YOLO를 빠른 뇌의 눈으로 쓰는 것은 몸이 가상 세계에 있으면 맞지 않는다. 가상 몸의 눈은 시뮬레이터가
  주는 정보(물체 위치, 렌더링 화면)다. 카메라는 실제 몸이 생겼을 때 쓴다.
- 처음부터 휴대폰으로 가지 않고 PC 웹에서 시작한다 (이 PC에 Android 개발 환경이 없고, 실제 폰 연결이 필요하다).
  두뇌를 TypeScript로 써서 나중에 옮긴다.
- 언어 모델 지연 예상(0.5~2초)은 휴대폰 1~3B 모델에서는 낙관적이다. 그래서 언어 모델은 작전만 정하고 실시간 조종은 하지 않는다.
