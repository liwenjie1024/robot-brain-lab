# 구조

사람형 기체의 AI 두뇌를 시험하는 곳이다. 실제 휴머노이드처럼 층을 나누고, 층마다 빠르기와 쓰는 기술이 다르다.
시험 대상은 두뇌(System 1·2)이고, 몸과 비행·팔 제어(System 0)는 시험 장치다.

시험 기체는 애니메이션의 대형 기체 장르(날고 무장한 사람형)를 따른 **이 프로젝트의 독자 설계 BL-01**이다.
특정 작품의 이름·디자인·로고(건담 등은 반다이남코·선라이즈의 지식재산)는 쓰지 않는다.

| 층 | 하는 일 | 빠르기 | 쓰는 것 | 상태 |
|---|---|---|---|---|
| 몸 | 강체·관절·접촉·중력 물리, 사격 광선 | 500Hz (0.002초) | MuJoCo 3.17 (Python, Linux 컨테이너) | 2단계 완료 |
| System 0 비행 제어 | 비행 속도 명령 → 추진기 힘(위·앞뒤·옆·세 축 회전), 기체를 똑바로 | 500Hz | 속도·자세 되먹임 (질량·관성으로 나눔) | 2단계 완료 |
| System 0 팔 제어 | 겨눌 점 → 어깨 두 관절 각 → 관절 힘 (중력 보상) | 500Hz | 거꾸로 푼 각 + PD | 2단계 완료 |
| System 1 빠른 뇌 | 표적 고르기·바라보기·거리 유지·조준이 맞을 때 쏘기·경고를 보면 피하거나 막기. 언어 모델 없이 되먹임으로 | 50Hz (몸의 상태마다) | TypeScript (Node) | 2단계 완료 |
| System 2 느린 뇌 | 말로 한 명령 + 장면 요약 → 작전 계획(기술 단계) → 단계마다 빠른 뇌의 기술을 바꿈 | 첫 단계 0.9~2.1초, 계획 전체 0.9~3.5초 (짧은 명령·기억한 계획은 바로) | 로컬 언어 모델 (Ollama qwen2.5:7b, JSON 형식 강제, 흘려 받기) | 3단계 완료 |
| 시험장 화면 | 3D 모습·사격 광선, 기체 상태·위협 경고, 말로 명령하기(계획 단계·걸린 시간), 두뇌 칸(조종 맡기기·기술·판단 기록·지표), 직접 조종·사격, 전투·명령 기록 | 화면 60fps | Vue 3 + three.js | 3단계 완료 |

## 왜 이렇게 나누나

- **느린 뇌가 기체를 직접 움직이면 안 된다.** 언어 모델은 계획 하나에 수백 ms~몇 초가 걸린다. 드론의 조준 경고는 1.2초 뒤
  사격이라, 경고를 보고 피하거나 방패를 드는 일은 빠른 뇌가 해야 한다. 느린 뇌는 "무엇을 할지(어느 표적, 어떤 작전)"만 정한다.
- **몸은 시험 장치다.** 비행·팔은 고전 제어(되먹임)로 확실하게 움직이고, 두뇌는 그 위에서 속도·겨눌 곳·사격만 명령한다.
  사격은 겨눈 방향이 아니라 팔이 실제로 가리키는 방향으로 나가므로, 두뇌는 조준이 맞기를 기다려야 한다 (실제 로봇처럼).
- **두뇌는 TypeScript로 쓴다.** 나중에 두뇌만 휴대폰(React Native + llama.rn)으로 옮길 수 있게 한다. 몸과 두뇌는
  WebSocket 규약으로만 이어지므로, 두뇌가 PC에 있든 휴대폰에 있든 몸은 모른다.

## 기체 BL-01

- 키 16m, 질량 약 38.7t (모델에서 잼). 몸통·다리는 굳어 있고(비행 중심), 팔은 어깨 관절 두 개(돌리기·들기).
- 추진기: 기체 전체 무게 중심에 걸리는 위·앞뒤·옆 힘과 세 축 회전 힘 (MuJoCo 사이트 액추에이터). 힘 한도는 질량·관성에서 정한다
  (위로 오르는 가속 12m/s², 옆 가속 15m/s², 회전 가속 6rad/s²에 여유 1.2배).
- 무장: 오른팔 빔 소총 (사거리 1500m, 피해 30, 0.5초 식힘, 에너지 100에서 한 번에 20, 초당 8 충전).
- 방패: 왼손 앞에 팔과 직각으로 든 판 (반 폭 3m). 팔꿈치가 없어 팔을 막을 쪽으로 뻗어 든다 (`guard` 명령의 unit).
- 체력 1000. 0이 되면 추진기가 꺼지고 떨어진다.

## 시험 장면

| 장면 | 내용 |
|---|---|
| empty | 드론 없이 날기·자세만 |
| targets | 멈춰 떠 있는 드론 3대 (150~260m), 반격 없음 |
| moving | 원을 그리며 나는 드론 3대 (반지름 60~100m, 15~25m/s), 반격 없음 |
| skirmish | 원을 그리며 나는 드론 3대가 조준 경고 1.2초 뒤 사격 (피해 40, 3초마다, 드론마다 1초씩 엇갈려 시작) |

드론은 시험 장치라 추진기를 흉내 내지 않고 힘을 바로 걸어 정한 길을 따라간다. 모델의 드론 수는 4대로 고정하고
(화면이 받는 모양이 바뀌지 않게), 장면에서 쓰지 않는 드론은 시험장 밖에 세워 둔다.

## 빠른 뇌 System 1 (brain/)

몸의 상태가 올 때마다(50Hz) 아래를 한 번에 한다. 판단 한 번은 약 15µs다.

1. **보이는 것**(`perception`): 상태 → 내 상태, 살아 있는 드론(거리·기수에서 돌아간 각·무장), 위협(쏘기까지 남은 초).
2. **기술**(`skills/`): 사람이나 느린 뇌가 고른 것 하나.
   - 대기: 멈춤. 자리 지키기: 기술을 고른 때의 자리를 붙잡고, 밀려나면 돌아온다.
   - 교전: 표적 고르기(무장·지금 조준 중·다친 드론을 먼저, 아주 낫지 않으면 표적을 바꾸지 않음), 기수를 표적으로,
     거리 띠(120~220m)와 높이 맞추기, 조준이 맞고(거리에 따른 허용 어긋남: 1m를 지나가는 각) 소총이 준비되면 쏘기.
   - 물러나기: 드론들 반대쪽으로 오르며 날고, 무장한 드론 쪽으로 방패.
3. **반사**(`reflexes`): 새 조준 경고를 보면 기술과 상관없이 곧바로 피하기(위협과 직각, 지금 속도와 반대쪽)·막기(가장 먼저
   쏠 드론 쪽)·둘 다. 새 경고마다 속도를 다시 바꾼다. 같은 경고가 이어지는 동안은 다시 시작하지 않는다.
4. **명령 담당**(`commander`): 의도 → 지난번과 달라진 명령만 몸에 보낸다. 사격은 앞 사격의 답이 오기 전에 다시 보내지 않는다.
5. **기록·지표**: 판단 기록(기술·표적·사격·반사·결과·거절), 판단 시간, 반응 시간(경고를 본 때 → 반사 명령을 몸이 받은 때), 명중·격파·피해.

두뇌가 조종을 맡지 않으면 명령은 보내지 않고 "두뇌라면 이렇게 함"만 화면에 보인다.

## 느린 뇌 System 2 (brain/src/system2/)

말로 한 명령을 계획으로 바꾸고, 계획의 단계마다 빠른 뇌의 기술을 바꾼다. 기체를 직접 움직이지 않는다.
계획을 짜는 동안에도 빠른 뇌는 50Hz로 지금 기술을 하며 조준 경고를 피하고 막는다.

1. **어디서 계획을 얻나** (차례로 본다)
   - 짧은 명령(`quickOrders`): "공격·물러나·멈춰·자리 지켜"처럼 말 전체가 정해 둔 낱말이면 언어 모델 없이 바로.
   - 기억한 계획(`planCache`): 같은 명령을 같은 상황(장면, 살아 있는 드론)에서 받았으면 그때 계획을 다시 확인해 쓴다.
   - 언어 모델(`model`·`prompt`): Ollama qwen2.5:7b에 규칙·예 두 개(시스템 글), 장면 요약(드론 id·거리·체력·무장·나를 겨누는지)과 명령을 준다.
     답의 모양은 `format`으로 강제한다 (계획 스키마에서 $ref를 풀고 피하기에서 none을 뺀 것). 온도 0.2, 30분 동안 GPU에 둔다.
2. **계획 형식**(`contracts/brain/plan.schema.json`): `say`(한 문장), `retreatBelowHp`(이 체력 비율 아래면 물러남),
   `steps` 1~5개(`skill`, `target`, `evasion`, `until`: targetDestroyed·allDestroyed·seconds·hpBelow·never, `value`).
   모든 필드를 늘 채우고 oneOf를 쓰지 않는다 (작은 모델이 잘 따르게). retreatBelowHp를 단계보다 먼저 쓰게 해 첫 단계를 시작할 때 이미 안다.
3. **흘려 받기**(`planStream`): 답을 글 조각으로 받으며 단계 하나를 다 받는 대로 확인해 바로 시작한다 (계획 전체를 기다리지 않음).
4. **확인**(`planCheck`): 모양은 스키마로, 뜻은 규칙으로 본다 — 표적은 engage에만·장면에 살아 있는 드론만, 격파 조건(targetDestroyed·
   allDestroyed)은 engage에만(쏘는 기술은 engage뿐), hpBelow는 engage·hold에만, value 범위, never 뒤 단계 없음.
   틀린 것이 보이면 끝까지 기다리지 않고 끊고, 지난 답과 까닭을 붙여 한 번 더 묻는다. 두 번 다 틀리거나 30초 안에 답이 없으면 실패로 알린다.
5. **따르기**(`planRun`): 몸의 상태가 올 때마다 지금 단계의 until을 본다. 한 번에 여러 단계가 맞으면 건너뛰고, 다음 단계를
   아직 받지 못했으면 기다린다. 체력이 retreatBelowHp 아래면 단계를 멈추고 피하며 막으며 물러난다. 기체가 파괴되면 실패.
6. **사람이 앞선다**(`brain`): 사람이 기술을 직접 고르거나 조종을 가져가면 계획을 그만둔다. 새 명령·그만두기는 묻던 요청을 끊고,
   늦게 온 답은 버린다. 몸이 처음으로 되돌아가면 계획을 그만둔다. 그만둬도 기체는 지금 기술을 그대로 한다.
7. **언어 모델이 없으면** 짧은 명령만 따르고, 다른 명령은 까닭(예: 쓸 수 있는 짧은 명령)을 붙여 실패로 알린다. 15초마다 다시 찾는다.

## 데이터 흐름

```text
시험장 화면 ──GET /scene──────────────▶ 몸(sim :8765)   모양·유닛·시험 장면·명령 범위 (한 번)
시험장 화면 ◀──WS /ws  state 50Hz──────── 몸            몸체 자세, 기체 상태(모드·체력·에너지·소총·방패), 드론, 위협
            ◀──WS /ws  shot·destroyed──── 몸            사격(어디서 어디로, 맞힘·막힘)·격파 사건 (빠짐없이)
두뇌·화면   ──WS /ws  velocity/aim/fire/guard/reset──▶ 몸   명령 → ack 또는 rejected(까닭). 답 → 그 명령의 사건 → 상태 순서
두뇌(:8766) ──WS brainStatus 5Hz·decision──▶ 화면(/brain)   두뇌 상태·지금 하는 일·지표·계획·언어 모델, 판단 기록 (생길 때마다)
화면        ──WS setSkill/setAutonomy/order/cancelPlan──▶ 두뇌   지시 → controlResult(받음·거절 까닭). 계획의 진행은 상태로 알림
두뇌        ──HTTP /api/chat (흘려 받기)──▶ Ollama(:11434)   계획 묻기. /api/tags로 모델이 있는지 본다
```

규약은 `contracts/sim/*.schema.json`(몸)과 `contracts/brain/*.schema.json`(두뇌) 한 곳에서 정하고, 타입은 `npm run contracts`로 만든다. 몸은 같은 스키마로 명령을, 화면은 같은 스키마로 메시지를 검증하고,
몸의 시험(`tests/test_contracts.py`)이 실제로 내보내는 메시지가 스키마에 맞는지 확인한다.

## 빠른 뇌를 실제로 돌려 잰 값 (2026-11-03, 이 PC)

교전 기술을 맡기고 60초 동안 돌렸다 (처음 1~2번의 피해는 두뇌가 맡기 전에 드론이 쏜 것이다).

| 장면 · 조준 경고 반응 | 다 격파한 때 | 맞음 / 막음 / 빗나감 | 받은 피해 | 명중 |
|---|---|---|---|---|
| 멈춘 표적 3대 | 17.4초 | - | 0 | 6/6 |
| 반격하는 드론 · 반응 안 함 | 25.8초 | 11 / 0 / 5 | 440 | 6/6 |
| 반격하는 드론 · 피하기 | 30.7초 | 2 / 0 / 14 | 80 | 6/6 |
| 반격하는 드론 · 방패로 막기 | 22.3초 | 3 / 3 / 6 | 120 | 6/6 |
| 반격하는 드론 · 피하며 막기 | 30.7초 | 2 / 1 / 13 | 80 | 6/6 |

- 판단 한 번 평균 15~16µs(가장 길게 0.2ms 안), 조준 경고를 본 때부터 반사 명령을 몸이 받기까지 17~19ms.
- 피하기는 피해가 가장 적지만 기체가 움직여 조준이 늦어진다. 막기는 조준이 흔들리지 않아 가장 빨리 끝낸다.
- 거리에 따른 사격 허용 어긋남을 쓰기 전(0.5° 고정)에는 멈춘 표적에서 9번 쏘아 6번 맞혔다(멀리서 2m쯤 빗나감).

## 느린 뇌를 실제로 돌려 잰 값 (2026-11-06, 이 PC, qwen2.5:7b, RTX 4060 Ti)

반격하는 드론 장면에서 말로 명령했다. 시간은 명령을 보낸 때부터다. 언어 모델이 따뜻할 때 첫 글자는 40~80ms
(시스템 글을 바꾼 뒤 처음 묻는 명령은 0.3~0.7초), 초당 약 48토큰이다.

| 명령 | 어디서 | 첫 단계 시작 | 계획 전체 | 물은 횟수 | 짠 계획 |
|---|---|---|---|---|---|
| 체력이 적은 드론부터 잡고, 방패로 막으면서 싸워. 위험하면 물러나. | 언어 모델 | 2.1초 | 3.5초 | 1 | 드론 3→1→2 차례로 교전(막기) → 자리 지키기, 체력 30% 아래면 물러남 |
| 드론 2부터 잡고 나머지도 정리해 | 언어 모델 | 1.1초 | 1.9초 | 1 | 드론 2 → 나머지 모두 → 자리 지키기 |
| 10초 동안 자리 지키다가 공격해 | 언어 모델 | 1.0초 | 2.3초 | 1 | 10초 자리 지키기 → 드론 1 → 나머지 → 자리 지키기 |
| 가장 가까운 무장 드론을 먼저 쏘고, 체력이 절반 아래로 떨어지면 물러나 | 언어 모델 | 1.5초 | 4.0초 | 2 | 드론 1 → 물러나기, 체력 50% 아래면 물러남 (첫 답의 "물러나며 hpBelow"를 까닭과 함께 다시 물어 고침) |

| 피하면서 전부 격파해 | 언어 모델 | 0.9초 | 0.9초 | 1 | 모두 격파 (피하며 막기) → 자리 지키기 |
| 공격 | 짧은 명령 | 0초 | 0초 | 0 | 모두 격파 (피하기) → 자리 지키기 |

- 처음 시스템 글에서는 7B 모델이 말이 없는 피하기에 none(반응 안 함)을, 시간 말이 없는데 seconds를, 물러나는 단계에 hpBelow를 썼다.
  형식에서 none을 빼고, 뜻 확인에 규칙을 더하고(틀리면 까닭을 붙여 다시 물음), 규칙과 예를 고쳐 위처럼 되었다.

말로 명령해 60초 싸운 결과 (드론 3대 모두 격파, 명중 6/6 또는 6/7):

| 명령 (명령 전 가만히) | 계획 | 다 격파 | 명령 뒤 받은 피해 |
|---|---|---|---|
| 드론 2부터 잡고 나머지도 정리해. 위험하면 물러나 (0초) | 언어 모델, 피하며 막기 | 25.7초 | 0 |
| 방패로 막으면서 전부 격파해 (0초) | 언어 모델, 막기 | 20.6초 | 160 |
| 공격 (0초) | 짧은 명령, 피하기 | 35.2초 | 80 |
| 피하며 막으면서 전부 격파해 (0초) | 언어 모델, 피하며 막기 | 43.3초 | 40 |
| 공격 (14초) | 짧은 명령, 피하기 | 51.2초 | 40 |
| 피하며 막으면서 전부 격파해 (14초) | 기억한 계획, 피하며 막기 | 32.7초 | 40 |

- 언어 모델이 계획을 짜는 1~2초 동안에도 빠른 뇌가 피하고 막아, 명령 뒤 받은 피해는 0~160이다 (가만히 있던 14초 동안에는 400).
- 다 격파하기까지는 21~51초로 판마다 크게 다르다. 드론 셋이 번갈아(약 1.4초마다) 조준하면 반사가 거의 쉬지 않고,
  피하는 동안에는 겨누지 못해 반사가 쉬는 틈에만 쏜다. 한 판만으로는 반응 방법을 비교할 수 없다.
- 피하는 동안 돌기를 멈추지 않게 바꿔 같은 조건으로 6판 재 보았으나 18.3~48.2초로 나아지지 않아 되돌렸다.

## 다음 단계

1. **시험 장면과 점수:** 장면·명령마다 여러 번 돌려 격파 시간·받은 피해·명중률·반응 시간·계획 시간을 모아 비교한다
   (한 판으로는 21~51초처럼 흩어져 비교할 수 없다).
2. **드론 셋이 번갈아 조준할 때 쏠 틈:** 반사가 쉬지 않아 겨누지 못한다. 가장 먼저 쏠 드론만 피하고 나머지는 막는 식으로 나눠 점수로 비교한다.
3. **느린 뇌가 스스로 다시 계획:** 지금은 명령을 받을 때 한 번 짠다. 계획이 끝나거나 상황이 크게 바뀌면(드론이 늘어남 등) 스스로 다시 묻는다.
4. 나중에: 팔꿈치·근접 무기(빔 사벨), 기체끼리의 대전, 두뇌를 휴대폰으로 옮기기, 기체가 여럿이면 관제용 MQTT.
