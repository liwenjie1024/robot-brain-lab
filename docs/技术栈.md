# 技术栈

用了什么、哪个版本、为什么。加库、换库要改这份。
规则：版本写死；新版本发布超过两周才用；新的东西先查许可证（[AI 模型](AI模型.md) 第 10 节）。

这里只列**已经在用的**。计划要用的（ROS 2、rmw_zenoh、各个模型）在 [系统结构](系统结构.md) 和 [AI 模型](AI模型.md) 里，用到的时候再加进来。

| 用在哪 | 技术 | 版本 | 为什么 | 没选的 |
|---|---|---|---|---|
| 身体：运行环境 | Python，在 Docker 的 Linux 容器里 | `python:3.13.18-slim`，按 digest 写死（`sha256:e48f59cd…ed90`） | 这台电脑的 Windows 会拦没有签名的 `mujoco.dll`，所以只在容器里跑。3.13 是上一个项目验证过的 | 直接在 Windows 上跑（要关安全设置，不行） |
| 身体：计算 | NumPy | 2.5.4 | 拟合"驱动器有多重"的幂律；以后的向量计算 | - |
| 身体：物理 | MuJoCo | 3.17.0 | 关节和接触准、快；能用代码（MjSpec）生成模型。上一个项目在这台电脑上验证过。P1 的 1.2 步开始用：生成身体的模型、在仿真里站着。实测 75 个自由度的身体约是实时的 15 倍 | Isaac Lab（要 16 GB 显存，这台电脑只有 8 GB） |
| 身体：基线的模型 | Unitree G1 的 MuJoCo 模型（MuJoCo Menagerie 的 `unitree_g1/g1.xml`，29 个自由度） | 提交 `cda5236f9838`（2026-10-20），清单在 `third_party/unitree_g1.json` | 现成的、公开的、能商用的身体，练好的权重（SONIC）就是给它练的。按清单下载，每个文件核对 SHA-256，不提交进仓库（`third_party.py`，只用 Python 自带的库） | 同一个目录里的 `g1_mjlab.xml`（没有驱动器和力矩的上限，要自己写）、`g1_with_hands.xml`（带三指的手，到比抓东西时再加）；把文件提交进仓库（20 MB 的网格会一直留在历史里） |
| 身体：画图 | 自己写的 SVG（`drawing.py`，只用 NumPy） | - | 把模型的每个形状投影成多边形，画正面和侧面；现成模型的网格画成凸包。不用显卡、不加库，画出来的文件每次一样，能放进报告 | MuJoCo 自带的渲染（要 OpenGL，现在的容器里没有；做网页（1.4）时再定 3D 怎么画） |
| 身体：检查 | pytest、Ruff | 9.2.0、0.17.3 | 测试；格式和代码规则 | - |
| 仿真：给网页的服务 | aiohttp | 3.14.5 | 一个库就有 HTTP 和 WebSocket；上一个项目在这台电脑上用的就是这个版本 | 只用 Python 自带的库（没有 WebSocket）；FastAPI（要再加一个服务器的库） |
| 规约 | JSON Schema（`contracts/sim`）；Python 用 jsonschema，网页用 ajv | jsonschema 4.26.0、ajv 8.20.0 | 消息长什么样只写一处，仿真和网页用同一份文件检查 | 两边各写一遍（会对不上） |
| 策略的规约 | JSON Schema（`contracts/policy`）：训练那边写，测试台读，两边都用 jsonschema 检查 | - | 练出来的策略看什么、出什么只写一处；对不上就不跑，不猜（系统结构 6.2 节） | 测试台照 mjlab 写在 ONNX 里的附加信息去猜（少了观测的长度、命令的范围、IMU 在哪） |
| 测试台：跑练出来的策略 | ONNX Runtime（只用 CPU，一个线程） | 1.31.1（它要的 flatbuffers 25.12.19、packaging 26.3、protobuf 7.36.2 也写死） | 测试台不用装 PyTorch（一两个 GB）；ONNX Runtime 也有 C++ 的，以后实时分区里用（系统结构 6.3 节） | 测试台装 PyTorch |
| 训练：运行环境 | Python，在 Docker 的 Linux 容器里，用显卡（Docker Desktop 的 GPU）；库用 uv 照 `train/uv.lock` 装 | 和身体同一个 `python:3.13.18-slim`（同一个 digest）；uv 0.13.7。锁的时候只要 2026-11-04 以前发布的（`exclude-newer`）；`uv sync --locked`：锁和 pyproject 对不上就不装 | 训练的库有 148 个，一个一个写死太容易漏；uv 的锁把每一个都写死，还带每个文件的 SHA-256 | conda（又多一套装库的办法）；NVIDIA 的 CUDA 镜像（几个 GB，PyTorch 的包里已经带着要用的 CUDA 库） |
| 训练：显卡上的仿真 | MuJoCo Warp + NVIDIA Warp | 3.17.0、1.18.0 | 和身体同一个 MuJoCo（3.17.0）；几千个仿真一起在显卡上跑。实测：显卡和 CPU 算一个方块落地一样；Nova 的模型不用改就放得进去，站 1 秒和 CPU 一样 | Isaac Lab（要 16 GB 显存） |
| 训练：强化学习的框架 | mjlab（Isaac Lab 那样的写法，跑在 MuJoCo Warp 上）+ rsl-rl（PPO） | mjlab 1.6.0（GitHub 的提交 `dcdf6ce`，2026-11-01）、rsl-rl-lib 5.5.2；mjlab 直接用的库按它那一版自己测过的版本写死 | 有现成的 G1 走路、动作跟踪的任务；和身体用同一种模型（MJCF、MjSpec）。那一版写的是 MuJoCo 3.16，我们用 uv 的 override 装 3.17：它的 G1 走路练得出来，策略在测试台上走得起来 | mjlab 新的一版（换成了 MuJoCo 4.0，出来不到两周） |
| 训练：神经网络 | PyTorch（CUDA 13.0 的版本） | 2.14.0+cu130 | mjlab 那一版测过的；这台电脑的显卡驱动（596.49）支持到 CUDA 13.2 | cu126 的版本（也行，mjlab 两种都测过） |
| 训练：导出策略、看训练的曲线 | onnx、onnxscript（导出 ONNX）；TensorBoard（记录写在 `results/`） | 1.22.0、0.5.4；2.20.0 | 都不连网。mjlab 默认用 wandb（把记录发到它的网站），关掉了（`WANDB_MODE=disabled`、`--agent.logger tensorboard`） | wandb |
| 实时分区：语言和编译 | C++20；g++、CMake、Ninja（Debian 13 的软件源，版本写死），在身体的镜像的第一段里编译；警告都当错误（`-Wall -Wextra -Wpedantic -Wconversion -Werror`） | g++ 14.2.0、CMake 3.31.6、Ninja 1.12.1 | 系统结构 6.3 节定的：脊髓层、小脑层 1 kHz 硬实时，Python 做不到（垃圾回收、全局锁）；ros2_control 也是 C++ | Rust（生态里没有 ros2_control） |
| 实时分区：矩阵运算 | Eigen（只有头文件） | 3.4.0 | 用得最广的 C++ 矩阵库，和 MuJoCo、Pinocchio 一起用的多；以后状态估计（InEKF）也用它 | - |
| 实时分区：测试 | GoogleTest（`docker compose run --rm rt`：编译、跑 C++ 的测试） | 1.16.0 | 最常用的 C++ 测试框架；每个测试上面一行中文的 `// 说明：` | Catch2 |
| 实时分区：给测试台（Python）用 | nanobind + scikit-build-core：编译成 Python 的模块 `nova_rt`，装进身体的镜像 | nanobind 3.1.0、scikit-build-core 1.1.1（还要 pathspec 1.1.1、packaging 26.3） | 测试台每 1 毫秒调用一次脊髓层，同一个进程里调用最快；nanobind 比 pybind11 快、小 | pybind11；分成两个进程、经消息系统（2.8 步再做） |
| 网页：运行环境 | Node.js（直接在这台电脑上跑，不在容器里） | 24.15.0 | 网页的工具没有被智能应用控制拦住；上一个项目就是这样跑的 | 放进容器（要多一个镜像，改了代码刷新也慢） |
| 网页：框架和界面 | Vue 3 + TypeScript + Naive UI | vue 3.5.44、typescript 5.9.3、naive-ui 2.45.3 | [系统结构](系统结构.md) 6.3 节定的，和上一个项目一样；版本也一样，这台电脑上验证过 | - |
| 网页：3D | three.js | 0.186.1（类型 @types/three 0.186.0） | 在浏览器里用显卡画 3D。身体的形状从仿真拿，网页不认身体是哪一个 | 在仿真那边渲染成图片再传过来（容器里没有 OpenGL，也慢） |
| 网页：开发和打包 | Vite（插件 @vitejs/plugin-vue） | 8.3.4（6.0.10） | 开发时改了代码马上看到；把发给仿真的请求转过去，网页和仿真就是同一个地址 | - |
| 网页：检查 | Vitest（jsdom、@vue/test-utils）、ESLint（eslint-plugin-vue、@vue/eslint-config-typescript）、vue-tsc | vitest 5.0.5、jsdom 30.1.3、@vue/test-utils 2.5.1、eslint 10.13.0、eslint-plugin-vue 10.11.1、@vue/eslint-config-typescript 14.9.0、vue-tsc 3.3.13、@vue/tsconfig 0.9.1、@types/node 24.19.2 | 测试；代码规则；类型检查 | - |
| 网页：照规约生成类型 | json-schema-to-typescript | 16.0.0 | 网页里消息的类型是照 JSON Schema 生成的，不手写 | - |

许可证：Python（PSF）、NumPy（BSD-3）、MuJoCo（Apache 2.0）、pytest（MIT）、Ruff（MIT）、Unitree G1 的模型（BSD-3）、aiohttp（Apache 2.0）、jsonschema（MIT）、Node.js（MIT）、TypeScript（Apache 2.0）、Vue、Naive UI、three.js、Vite、Vitest、jsdom、ESLint、vue-tsc、ajv、json-schema-to-typescript（都是 MIT），都可以商用。
训练和跑策略的：PyTorch（BSD-3 为主）、Warp、MuJoCo Warp、mjlab、ONNX、TensorBoard（Apache 2.0）、rsl-rl（BSD-3）、onnxscript、ONNX Runtime（MIT）、uv（MIT 或 Apache 2.0），都可以商用。训练的容器里还有几样不随机器人发出去的（NVIDIA 的 CUDA 库、GPL 和 LGPL 的几个小库），见 [AI 模型](AI模型.md) 第 10 节。
实时分区（C++）的：Eigen（MPL-2.0）、GoogleTest（BSD-3）、nanobind（BSD-3）、scikit-build-core（Apache 2.0）、CMake（BSD-3）、Ninja（Apache 2.0），都可以商用；编译器 g++ 是 GPL，但有运行库的例外，编译出来的程序不受 GPL 限制。
