# 质量闭环的结果

**这份报告是程序算出来的，不要手改。** 要改就改 `body/nova_body` 里的假设，再运行：

```bash
docker compose run --rm body python -m nova_body.mass_report
```

质量闭环是什么：腿和躯干要出的力矩跟着体重变。身体重了，腿的驱动器就要更大、更重，身体又更重。
把这个循环算到不再变，得到的就是体重。

## 1. 结论

| 身体 | 自由度 | 驱动的假设 | 体重 | 多带 1 kg，总重加多少 |
|---|---|---|---|---|
| 核心版 | 75 | 今天最好的驱动 | **74 kg** | 1.69 kg |
| 核心版 | 75 | 保守的驱动 | **88 kg** | 1.93 kg |
| 完整版 | 98 | 今天最好的驱动 | **92 kg** | 1.71 kg |
| 完整版 | 98 | 保守的驱动 | **111 kg** | 1.99 kg |

- **今天最好的驱动**：按 8 个真实产品的数拟合，包括每公斤力矩最大的那个（Unitree M107，厂商的数）。
- **保守的驱动**：去掉最好的那个再拟合。
- 两个都是按**峰值**力矩算的。真实的体重大概在两者之间。

## 2. 每样东西加多少重量

基准：核心版、今天最好的驱动，**74.2 kg**。

| 改动 | 体重 | 和基准差 |
|---|---|---|
| 不要液冷 | 69.1 kg | -5.1 kg |
| 不要保底的东西（双绕组、超级电容、制动器、安全板） | 66.4 kg | -7.8 kg |
| 电池从 1 kWh 加到 2.3 kWh | 85.1 kg | +10.9 kg |
| 手换成全肌腱的（A） | 78.7 kg | +4.4 kg |
| 骨架占总重的 25%（基准是 20%） | 81.1 kg | +6.9 kg |
| 驱动器按人的峰值（初估）定，不按动作算的 | 80.2 kg | +6.0 kg |
| 力量减半（轻的家用身体） | 57.4 kg | -16.9 kg |
| 完整版（98 个自由度，全肌腱的手） | 91.5 kg | +17.3 kg |

## 5. 用的假设

| 项目 | 取值 |
|---|---|
| 身高 | 1.7 m |

| 规格里的峰值力矩对应的体重 | 70 kg；腿和躯干的力矩按实际体重等比例放大 |
| 骨架 | 占总重的 20% |
| 线 | 占总重的 4% |
| 电池 | 1 kWh，每公斤 200 Wh（高倍率的电池包） |
| 电脑 | 1.5 kg |
| 液冷（泵、散热器、冷却液、管） | 3 kg |
| 皮肤、软外壳、外衣 | 3.5 kg |
| 传感器（相机、麦克风等） | 1 kg |
| 脚里的东西（踝的六轴力传感器、脚底的压力皮肤、脚板） | 每只脚 0.6 kg |
| 超级电容 | 1 kg |

## 7. 这个模型还不知道的

- **速度**：只按峰值力矩算重量，没算要转多快。每个关节要的转速在[力量的报告](力量.md)里，按转速、发热选电机是 1.6 步的事。
- **持续的力**：峰值只能出一小会儿。能一直出多大的力要看散热，这里没算。
- **推杆**：没有核实过的重量数据，先按旋转驱动器算。
- **手**：三种手的重量都是估的。
- **骨架**：按总重的固定比例算，没有按受力算。
- **肩胛**：推杆要多大的力还没测，按每个 0.3 kg 估。
