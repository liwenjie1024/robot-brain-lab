# 质量闭环的结果

**这份报告是程序算出来的，不要手改。** 要改就改 `body/nova_body` 里的假设，再运行：

```bash
docker compose run --rm body python -m nova_body.mass_report
```

质量闭环是什么：腿和躯干要出的力矩跟着体重变。身体重了，腿的驱动器就要更大、更重，身体又更重。
把这个循环算到不再变，得到的就是体重。

## 1. 结论

| 身体 | 自由度 | 驱动的假设 | 体重 | 多带 1 kg，总重加多少 |
|---|---|---|---|---|
| 核心版 | 75 | 今天最好的驱动 | **78 kg** | 1.73 kg |
| 核心版 | 75 | 保守的驱动 | **97 kg** | 2.01 kg |
| 完整版 | 98 | 今天最好的驱动 | **96 kg** | 1.74 kg |
| 完整版 | 98 | 保守的驱动 | **121 kg** | 2.06 kg |

- **今天最好的驱动**：按 8 个真实产品的数拟合，包括每公斤力矩最大的那个（Unitree M107，厂商的数）。
- **保守的驱动**：去掉最好的那个再拟合。
- 两个都是按**峰值**力矩算的。真实的体重大概在两者之间。

## 2. 每样东西加多少重量

基准：核心版、今天最好的驱动，**78.2 kg**。

| 改动 | 体重 | 和基准差 |
|---|---|---|
| 不要液冷 | 73.0 kg | -5.2 kg |
| 不要保底的东西（双绕组、超级电容、制动器、安全板） | 69.7 kg | -8.5 kg |
| 电池从 1 kWh 加到 2.3 kWh | 89.3 kg | +11.1 kg |

## 7. 这个模型还不知道的

- **速度**：只按峰值力矩算重量，没算要转多快。要等"从动作反推驱动"做完。
- **持续的力**：峰值只能出一小会儿。能一直出多大的力要看散热，这里没算。
- **推杆**：没有核实过的重量数据，先按旋转驱动器算。
- **手**：三种手的重量都是估的。
- **骨架**：按总重的固定比例算，没有按受力算。
- **肩胛**：推杆要多大的力还没测，按每个 0.3 kg 估。
